# Issue #3503: canonical managed deployment client

## Approval and scope

The owner approved this hardening scope on 2026-09-25. The approval covers the reviewed security, identity, provenance, recovery, and evidence fixes while preserving the successful deployment journey. It does not authorize merge, release, deployment, activation, billing, or destructive live tests.

Canonical amendment: https://github.com/enterpriseaigroup/Issues2025/issues/3503#issuecomment-5826177803

## Preserved user contract

- `eai deploy app <app-key> --target eai` remains canonical.
- Every initial, resume, and retry command supplies the exact `--target-tenant-id`; same-tenant deployments repeat `--tenant-id` explicitly.
- `eai-managed` and `customer-owned` remain explicit source choices.
- EAI-maintained publication remains bot-owned; customers do not push to or merge in an EAI repository.
- Customer-owned source remains governed in the customer's repository.
- Existing successful status vocabulary and resume/retry commands remain supported.
- Gofer guides; the CLI and platform execute.

## Requirements

- **DTE-009 through DTE-011, DTE-014:** require an explicit runtime tenant and bind the exact browser-link session plus numeric GitHub identity to the local `gh` actor that performs customer-owned repository actions.
- **DTE-016:** retain bounded, no-follow local publication and complete source digests. Bind the requested application-root inode and every ancestor across canonical resolution, and revalidate that root binding through local source inventory, Git reads, configuration hashing, canonical installation, and receipt writes. Bind each opened local source file to the inode that passed the initial bounded-file check, then revalidate the opened inode against the contained canonical path and unchanged ancestors before reading. Persist local receipts, retry authority, dispatch claims, and other private recovery files through opened confined regular-file descriptors rather than path-based renames. Recheck a private file's opened size before allocation. Write canonical generated bytes directly through an opened, path-bound regular-file descriptor, use exclusive creation when the target was absent, bind an existing target to its pre-open identity, and perform no path-based rename after bytes exist. Read caller-selected workflow evidence through the same bounded no-follow regular-file contract, including every parent identity plus a post-read descriptor/path/size check, before parsing or authenticated submission.
- **DTE-018, DTE-095:** compute and submit one exact `configHash` through no-follow file handles over every governed configuration source and runtime-provenance input, including nested `.test.*` and `.spec.*` files and the deployment contract, for both source modes. Exclude only the two deterministic generated Object Type outputs, reject links in every governed path component plus every nonregular filesystem entry, and recheck the opened file, ancestors, contained path, size, modification time, and change time after reading. Repeat the complete governed inventory and reject additions, removals, or substitutions before returning the digest, so the CLI and collector hash the same stable checked-out source manifest.
- **DTE-019, DTE-020, DTE-021, DTE-088:** consume exact template candidate bytes now, validate workflow inputs and collector parity, and keep the immutable released tag/commit as a deferred release gate without predicting a version. The candidate manifest must name only the canonical `.github/workflows/eai-app.yml` and `scripts/source-unknown-deployment-evidence.mjs` paths. The release gate must resolve the declared tag from the canonical template repository, prove that it names the exact reviewed candidate commit, and fetch both canonical remote files at that commit to verify their bytes against the pinned digests. Canonical evidence accepts both legacy `source-unknown-*` and managed `cli-managed-source-*` operation identifiers. Unified source revision proof includes canonical lowercase 40-hex `workflowBlobSha` and lowercase algorithm-qualified `collectorDigest` that the platform derives, verifies, and seals from the exact source commit. The isolated handoff must validate the exact source commit's canonical schema-provenance shape, digests, safe-line values, and approved anchor before OIDC.
- **DTE-022, DTE-023, DTE-025:** consume the template's immutable supply-chain pins, credential isolation, and runner-temporary bounded artifact staging so the upload action never reads the mutable build path directly and the staged archive digest remains bound through evidence. The isolated handoff must hash the downloaded archive through a fixed-size no-follow buffer with its 10 GiB bound and file identity revalidated, never through a whole-file allocation. Generated producer files must use exclusive no-follow creation before any destructive write; governed producer reads bind device, inode, size, modification time, and change time from the pre-open snapshot; GitHub command-file appends revalidate the bound leaf after writing.
- **DTE-025, DTE-026:** keep the CLI's canonical direct `workflow_dispatch` behavior unchanged while embedding the producer's retained `workflow_call` compatibility. The embedded workflow must reject a caller event other than `workflow_dispatch` before checkout, keep the deprecated long-lived EAI secrets unused, and document the reusable caller's required permissions. PublicAPI is the signed authority that permits only a complete same-repository, same-ref caller/callee OIDC claim set with the canonical callee path and exact source SHA.
- **DTE-031 through DTE-036, DTE-080:** bind dispatch, resume, retry, and terminal success to the exact operation, nonce, actor, tenant, source, workflow, commit, configuration, artifact, image, deployment, doctor, and target; make dispatch recovery safe after a lost response or crash; never select a latest operation. Validate every operation and tenant identifier as an opaque safe path segment before context resolution or any network request. When recovery omits `--source`, select the handler only from the unified exact operation's sealed `sourceMode`, never from the operation prefix or a fallback. Compare protected retry state with the server setup before accepting terminal or reusable-evidence responses. A terminal failed source status without accepted evidence requires a new operation and nonce. EAI-maintained completion requires a canonical merged SHA that exactly equals the unified revision commit. Success requires exact `requiresTenantInfra: true`, root `sourceStatus` in `handoff_pending` or `completed`, root and deployment `status: active`, `doctor.ready: true`, exact deployment/doctor identity, and the complete exact `sourceRevision` binding defined by the unified operation route. False, missing, or non-boolean TenantInfra markers remain pending.
- **DTE-091:** enforce the regional PublicAPI allowlist before tenant-context resolution and again at the authenticated client boundary for all managed and legacy source-unknown calls, including membership, tenant-management, app-validation, workflow-evidence, and other legacy source setup requests. Allowlist every browser-link, upload, and status origin before sending credentials. Reject redirects across every authenticated setup and operation boundary. Load protected retry state before the first retry request. Every retry request, including the source-unspecified unified-operation lookup, uses a client constructed from the exact originally selected PublicAPI URL; missing local endpoint authority fails closed without network access.
- **DTE-036, DTE-061, DTE-080:** add portable, operation-bound doctor evidence while retaining the existing URL-only doctor command. Authenticated readiness requires the passing canonical `GET /api/eai/readiness` probe, not an unrelated authenticated smoke test. Evidence output must remain beneath the resolved application root, reject a link in every parent component, and bind the opened output inode to the still-contained final path before writing owner-only bytes.
- **DTE-086, DTE-087:** integrate current `main` semantically, keep each managed-deployment command and client TypeScript implementation module under the repository's 300-line maintenance limit, preserve the public import paths, return failures through the repository-standard JSON error envelope, and rerun repository-owned checks on the exact head.
- **DTE-016, DTE-031 through DTE-035:** apply one bounded opaque identifier contract to every caller-controlled recovery or handoff operation ID before context resolution, local authority lookup, or network access. Bind only the exact macOS `/tmp` and `/var` system aliases to their expected canonical targets; reject arbitrary root-level links and revalidate allowed alias identities throughout filesystem access.

## Acceptance

1. The embedded workflow and evidence collector match the approved template candidate byte-for-byte and declare every CLI dispatch input; the workflow independently validates canonical source provenance before OIDC, the collector rejects pre-open file rewrites and hard-linked generated outputs, and release remains blocked until a real canonical template tag resolves to that candidate commit.
2. A wrong browser-link session, local GitHub actor, nonce, tenant, source, workflow, or target fails before mutation.
3. A crash or lost dispatch response resumes the same operation without duplicate dispatch or an endless poll-only state.
4. Every managed PublicAPI route, including legacy source-unknown setup/deploy/status routes, and every browser upload/status origin is allowlisted before credentials are sent; redirects are rejected.
5. Doctor JSON can be written portably through a fully no-link parent path and binds readiness to the exact completed deployment operation; authenticated readiness passes only when the canonical readiness probe successfully uses its declared secret in a request header.
6. Owned CLI tests and release metadata checks exercise these contracts.
7. Help and consumer contracts expose the required initial `--source`, browser continuation `--github-link-session`, and exact `--target-tenant-id` controls.
8. Missing `--target-tenant-id` fails before identity, status, linking, upload, or repository requests in both source modes.
9. Producer-pin verification rejects alternate manifest paths even when their bytes match the approved digests.
10. A projected active deployment remains pending until the unified operation response contains exact `requiresTenantInfra: true`, the exact source status, complete source revision, matching root configuration and identity fields, matching deployment/doctor identity, and a passing operation-bound doctor result.
11. Managed deployment filesystem, operation-contract, and retry-state responsibilities remain behind the existing public module path and are implemented in focused TypeScript modules under 300 lines each.
12. Workflow evidence ingestion rejects linked, nonregular, empty, or oversized input before parsing, validation, OIDC resolution, or evidence submission.
13. Configuration hashing rejects a linked or non-directory ancestor such as `src -> outside` in both the CLI and byte-identical collector.
14. Configuration hashing includes `.test.*` and `.spec.*` files and changes for the exact same governed file set in the CLI and packaged collector, excluding only the two generated Object Type outputs.
15. Local source publication rejects a file swapped between its initial metadata check and no-follow open, before including bytes in a bundle.
16. JSON failures use `{ "ok": false, "error": { "code", "message", "nextAction" } }`, and the managed command and source clients remain behind their existing public paths while focused implementation modules stay below 300 lines.
17. Legacy exact-operation requests reject empty, traversal, delimiter-bearing, or otherwise unsafe operation and target-tenant path segments before any network request.
18. Retry state without its exact originally selected regional PublicAPI URL is rejected instead of inheriting the caller's current endpoint.
19. Release verification fetches the canonical workflow and collector at the resolved producer tag commit and rejects either remote byte mismatch.
20. Configuration/source reads and receipt/doctor writes revalidate the opened inode against the contained canonical path after open, so an ancestor replacement cannot redirect bytes outside the approved root.
21. Unified source revisions require exact `workflowBlobSha` and `collectorDigest` fields; missing or malformed trusted-producer identity remains pending or fails closed.
22. Customer-owned retry loads protected state before any request, sends every read and mutation to that state's original regional PublicAPI URL, and requires a new source operation for terminal failure without accepted evidence.
23. EAI-maintained completion rejects a missing, malformed, or revision-mismatched merged SHA.
24. Workflow evidence ingestion rejects linked or replaced parents and a file changed or shortened during the bounded read.
25. Canonical collector evidence accepts and validates its observed `sourceMode`, `targetTenantId`, `workflowBlobSha`, and `collectorDigest` fields without treating them as authority; malformed or extra fields fail closed.
26. Retry state, dispatch claims, and canonical generated files cannot be redirected through a replaced parent. Generated bytes are written only through the already opened and path-bound regular-file descriptor, with no path-based rename after bytes are written.
27. Configuration hashing repeats its governed inventory and rejects any addition, removal, path replacement, ancestor replacement, or opened-file mutation through the end of every read.
28. Bounded local source reads repeat their ancestor, contained-path, leaf, size, modification-time, and change-time checks after reading and reject a replacement before source bytes enter the bundle.
29. Recovery without `--source` reads the unified exact operation before selecting a source-mode handler; retry state is checked before terminal success or accepted-evidence reuse.
30. Unsafe target tenant text fails before context resolution or network activity, and operation-bound doctor evidence cannot be written outside the application root.
31. Private recovery reads reject an opened descriptor outside the byte bound before allocation, and generated-file installation cannot clobber a target that appears or changes between inspection and open.
32. The embedded workflow uploads only the runner-temporary archive created by the byte-identical collector's bounded staging command and carries its exact digest into evidence.

34. Source-unspecified customer retry reads the unified operation through the protected state's original PublicAPI URL even when tenant refresh selects another regional endpoint.

40. Managed tenant membership and tenant-management setup calls reject redirects before sending the bearer token.
