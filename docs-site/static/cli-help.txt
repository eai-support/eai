# EAI CLI Help Snapshot
Version: 3.7.5

Install / update the CLI:
npm install -g eai-cli

Canonical package:
npm install -g @enterpriseai/cli

Static fallback:
npm install -g @enterpriseai/cli --@enterpriseai:registry=https://eai-tools.github.io/eai/registry/

Persistent static fallback setup:
npm config set @enterpriseai:registry https://eai-tools.github.io/eai/registry/ --location=user
npm install -g @enterpriseai/cli

eai --help
==========

Usage: eai [options] [command]

Enterprise AI Platform CLI — scaffold, seed, deploy, and manage applications

Options:
  -V, --cli-version      output the version number
  --simple               Plain text output without colors or symbols (for screen
                         readers)
  --no-color             Disable colored output
  --color                Force colored output
  --profile <name>       Use a locally configured private profile
  --describe             Output JSON schema of all commands
  -h, --help             display help for command

Commands:
  init [options] [name]  Scaffold a new application
  dev [options]          Start local development server
  login [options]        Authenticate with Entra CIAM
  logout                 Clear stored authentication tokens
  env                    Manage environment variables
  types                  Manage Object Type definitions
  tenant                 Manage tenants on the platform
  user                   Manage users on the platform
  resources              CRUD operations on platform resources
  app|vertical           Manage apps under the active company tenant
  chat                   Chat with AI workflows
  workflow               Provision app workflow configs and inspect AI runtime
                         workflow bindings
  docs                   Document upload, classification, and indexing
  deploy                 Deployment management
  runtime                Validate the provider-neutral EAI app runtime contract
  verify [options]       Run platform connectivity checks
  doctor [options]       Diagnose common issues and suggest fixes
  whoami                 Show auth status and tenant info
  update [options]       Check for and install CLI updates
  provision              Provision platform resources for this app
  gofer                  Inspect and refresh Gofer-managed project assets
  template               Preview application template and UI component drift for
                         the current project
  blocks                 Discover AI-readable EAI UI block manifests
  publicapi              Call authorized PublicAPI V4 routes directly
  errors                 Explain EAI CLI errors and agent-safe recovery steps
  agent                  Show AI-agent discovery and recovery guidance
  help [command]         display help for command

Getting Started:
  eai init my-app     Scaffold an app with Gofer AI CLI assets
  eai login                Authenticate with Entra CIAM
  eai provision entra      Create Entra app registration for end-user auth
  eai provision entra --deauthorize --force Clean up app auth registration
  eai env pull             Sync app config from cloud
  eai types seed           Publish Object Types to the platform
  eai dev                  Start local development server

Development Workflows:
  # Define your types, validate them, then publish them
  eai types validate && eai types seed

  # See what is published for the active tenant
  eai resources schema
  eai app create "My App" --template eai-app-template

  # Query resources and inspect data
  eai resources list User --limit 10
  eai resources get User <id>

  # Check AI runtime workflow readiness before using chat
  eai workflow readiness strategy-monitor
  eai workflow status strategy-monitor
  eai workflow request strategy-monitor --reason "CEO strategy cockpit"

  # Check login, tenant, and API connectivity
  eai verify && eai doctor

Deployment:
  # Validate the host-neutral runtime contract before deploying
  eai runtime validate
  eai deploy env --provider generic

  # Set up GitHub Actions deployment
  eai deploy setup --repo org/name

  # Trigger deployment, check status, then doctor the deployed runtime
  eai deploy trigger && eai deploy status
  eai deploy doctor --url <deployed-url>

Machine-Readable Output:
  # Get structured JSON output for automation
  eai resources list User --format json
  eai tenant list --format json | jq
  eai verify calls --format json
  eai errors explain E101 --format json

  # Discover CLI structure for AI agents
  eai --describe
  eai agent guide --format json

AI Terminal Workflows:
  # New projects include Gofer commands, agents, scripts, hooks, and skills
  claude                   then run /0_gofer_start
  codex                    then ask Codex to use the 1_gofer_research skill
  gemini                   then run /gofer:1_gofer_research
  copilot                  uses .github/prompts and .github/skills

Updates:
  # Check/update the CLI, then maintain safe repo-local assets
  eai update --check       preview CLI, Gofer, and template status
  eai update               update the CLI and refresh safe Gofer assets

  # Preview repo-local Gofer asset updates before writing files
  eai gofer refresh --check preview managed Gofer asset updates for this repo
  eai gofer refresh        apply safe Gofer-managed asset updates with backups

  # Preview app-template and UI component drift before copying changes
  eai template check       review potential app or UI file updates without overwriting local work

  # Discover AI-readable UI blocks for Gofer and apps
  eai blocks list --readiness public-ready
                                  list foundation, product, addon, and demo block IDs
  eai blocks describe core.button
  eai blocks readiness     summarize public readiness and package-profile compatibility

  # Call any authorized PublicAPI V4 interface
  eai publicapi get /v4/identity/me --format json
  eai publicapi post /v4/geo/resolve-location --data '{"query":"Copenhagen"}'

  # Explain known errors for humans and AI agents
  eai errors list
  eai errors explain tenant_authorization_incomplete --format json

  # Follow the built-in AI-agent recovery loop
  eai agent guide

Accessibility:
  # Screen reader friendly output
  eai --simple <command>
  eai --no-color <command>

eai init --help
===============

Usage: eai init [options] [name]

Scaffold a new application

Arguments:
  name                         Name for the app (kebab-case)

Options:
  --from <repo>                GitHub repo URL or local path for template
                               (default:
                               "https://github.com/eai-tools/eai-app-template.git")
  --skip-prompts               Use defaults without interactive prompts
                               (default: false)
  --current-dir                Scaffold into the current directory instead of
                               creating ./<name> (default: false)
  --tenant <id>                Main company tenant ID (deprecated alias for
                               --company-tenant)
  --company-tenant <id>        Main company tenant ID that owns this app
  --parent-tenant <id>         Immediate parent company tenant ID for the new
                               child company
  --child-tenant <name>        Create or reuse a child company tenant display
                               name for the app runtime boundary
  --create-child-tenant        Prompt for a child company tenant instead of
                               using the selected company tenant
  --no-gofer                   Skip installing Gofer AI CLI assets
  --package-profile <profile>  Package profile to record for block catalog
                               discovery: external, internal, or hybrid
                               (default: "external")
  -h, --help                   display help for command

Gofer AI CLI assets are installed by default:
  .specify/ commands, scripts, templates, hooks, and memory folders
  .claude/ commands and agents for Claude CLI
  .system/skills and .agents/skills for Codex CLI
  .gemini/commands/gofer and .gemini/extension.json for Gemini CLI
  .github/prompts, .github/instructions, and .github/skills for GitHub Copilot

The default public template is pinned to the latest eai-app-template main
commit captured when this CLI release was cut. Use --from to override it with
another repo or local path.

Use --no-gofer only when you need a bare app scaffold.

eai login --help
================

Usage: eai login [options]

Authenticate with Entra CIAM

Options:
  --tenant-name <name>    CIAM tenant name
  --tenant-id <id>        CIAM tenant ID
  --scope <scope>         OAuth scopes
  --callback-port <port>  Localhost port to listen on for the OAuth callback
  -h, --help              display help for command

Examples:
  $ eai login
  $ eai login --tenant-name myorg --tenant-id 12345678-abcd-efgh-ijkl-123456789012
  $ eai login --callback-port 3476
  $ eai whoami

What happens next:
  - The CLI opens your browser to sign you in.
  - With --callback-port, the CLI still uses localhost and listens on that exact port.
  - For Codespaces, run 'gh codespace ports forward -c <codespace> 3476:3476' on your local machine and keep it running while you sign in.
  - If you only have one tenant-admin membership, it becomes active automatically.
  - If you have more than one, run 'eai tenant select' to choose the tenant to work with.

eai types --help
================

Usage: eai types [options] [command]

Manage Object Type definitions

Options:
  -h, --help          display help for command

Commands:
  seed [options]      Push Object Types to platform
  validate [options]  Validate Object Types against platform schema rules
  diff [options]      Compare local Object Types with remote platform
  pull [options]      Download remote Object Types to local TypeScript
  define              Interactive Object Type builder (coming soon)
  help [command]      display help for command

Workflow:
  1. Validate local definitions:
       eai types validate
  2. Login and select the active tenant:
       eai login
       eai tenant select
  3. Preview remote differences:
       eai types diff --tenant-key <key>
  4. Publish:
       eai types seed --tenant-key <key>
  5. Verify published schema:
       eai resources schema

eai user invite --help
======================

Usage: eai user invite|add [options]

Invite or add a user to a tenant with a tenant role

Options:
  --email <email>            Email address of the user to add
  --tenant <id>              Tenant ID to add the user to (defaults to the
                             active tenant)
  --role <role>              Tenant role to assign
                             (tenant-viewer|tenant-staff|tenant-builder|tenant-admin)
                             (default: "tenant-viewer")
  --role-definition-id <id>  Specific tenant role definition ID to assign
                             instead of a base role
  --first-name <name>        Optional first name for new invitations
  --last-name <name>         Optional last name for new invitations
  --message <message>        Optional invitation message
  --redirect-uri <uri>       Optional post-invite redirect URI
  --format <format>          Output format (text|json) (default: "text")
  -h, --help                 display help for command

Examples:
  $ eai user invite --email user@example.com --role tenant-viewer
  $ eai user invite --email user@example.com --tenant <tenant-id> --role tenant-admin
  $ eai user add --email user@example.com --role-definition-id <role-definition-id>

Use this command for normal tenant membership and role assignment. Do not use
tenant bootstrap-admin unless repairing first-admin access on an immediate child
tenant.

eai user role set --help
========================

Usage: eai user role set [options]

Set a tenant member role; by email this uses the V4 invite/add flow

Options:
  --tenant <id>      Tenant ID to update (defaults to the active tenant)
  --email <email>    Email address to add or update through the invite/add flow
  --member-id <id>   Existing tenant member/user ID for the direct role update
                     endpoint
  --role <role>      Role to assign. Email-based updates support
                     tenant-viewer|tenant-staff|tenant-builder|tenant-admin;
                     member-id updates support member|tenant-admin.
  --format <format>  Output format (text|json) (default: "text")
  -h, --help         display help for command

Examples:
  $ eai user role set --email user@example.com --role tenant-admin
  $ eai user role set --member-id <member-id> --role tenant-admin

For normal "add this person as tenant admin/member" requests, prefer email-based
commands because they can resolve existing users and create missing tenant
membership in one V4 flow.

eai provision entra --help
==========================

Usage: eai provision entra [options]

Create an Entra app registration for end-user auth (Auth.js)

Options:
  --force               Re-check the remote app registration even if
                        ENTRA_CLIENT_ID already exists locally (default: false)
  --rotate-secret       Rotate the existing ENTRA_CLIENT_ID secret and write the
                        new value to .env.local (default: false)
  --deauthorize         Remove tenant authorization and delete the Entra app
                        registration for cleanup (default: false)
  --client-id <id>      Client ID to deauthorize; defaults to ENTRA_CLIENT_ID in
                        .env.local
  --keep-registration   Only remove tenant authorization; do not delete the
                        Entra app registration (default: false)
  --redirect-uri <uri>  Additional OAuth redirect URI to register (e.g. a
                        deployed callback). Repeatable. Registered alongside the
                        local callback; the platform merges with existing URIs.
                        (default: [])
  --debug               Print product-safe diagnostic status and request
                        identifiers on failure (default: false)
  -h, --help            display help for command

Examples:
  $ eai provision entra
  $ eai provision entra --force
  $ eai provision entra --rotate-secret
  $ eai provision entra --deauthorize --force
  $ eai provision entra --redirect-uri https://abc.com/api/auth/callback/microsoft-entra-id

What happens:
  - Calls the platform provisioning API to create an Entra app registration
  - Writes ENTRA_CLIENT_ID and ENTRA_CLIENT_SECRET to .env.local
  - If the registration already exists, confirms ENTRA_CLIENT_ID without rotating the secret
  - With --rotate-secret, rotates the existing app registration secret through the platform API
  - With --deauthorize --force, removes tenant authorization, deletes the app registration, and removes local ENTRA_CLIENT_ID/SECRET
  - With --redirect-uri, registers the given deployed callback(s) in addition to the local one (the platform merges them with any already registered)

Diagnostics:
  - Uses the PublicAPI URL from the active profile, .env.local BASE_URL_PUBLIC_API, environment, or the default API
  - Default/no profile uses the public API; private profiles use their locally configured API
  - The platform chooses the matching CIAM from its deployment configuration; the CLI never sends a CIAM selector
  - Errors are product-safe and include a support reference without exposing platform internals
