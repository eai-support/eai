## Persona

**Role**: Compliance technology developer at a financial services company subject to oversight from multiple regulatory bodies.

The compliance team tracks filing deadlines in spreadsheets, sends reminder emails manually, and maintains audit logs in shared documents. When regulators request proof of compliance, assembling the evidence is a multi-day effort. The company needs a system that tracks every obligation, automates deadline awareness, and maintains an immutable audit trail.

## Business Problem

Missed regulatory filings result in fines, enforcement actions, and reputational damage. The compliance team manages hundreds of recurring obligations across different regulations and entities, each with unique frequencies and deadlines. Without a structured system, obligations fall through the cracks, filings are submitted late, and there is no reliable audit trail showing when actions were taken and by whom. This scenario builds a compliance monitoring workflow that catalogs obligations, tracks filings against deadlines, and records every action in an audit trail.

## Four-Step Application

This scenario works best as a four-step, human-in-the-loop application. The existing object model already gives this scenario a strong delivery backbone through Obligation, Filing, and AuditTrail.

- **Mission metric focus:** faster matter turnaround, stronger risk control, and higher knowledge reuse.
- **Human + AI pattern:** Each step combines structured workflow data with chat assistance, background generation, document understanding, and accessible interaction patterns when they improve the experience.

### Step 1. Capture demand and context

- **Goal:** Make it easy for the user to start the Compliance Monitoring journey with complete, trusted context.
- **Required data:** Obligation context such as regulation, entity, description, and frequency.
- **AI support:** Use chat to guide intake, generate clearer prompts, create accessible summaries, and assist with voice or vision-led capture when a form alone is not the best experience. EAI can support structured intake, chat workflows, and document-centred capture today; richer native multimodal capture may still need workflow extensions or connected services.
- **Business impact:** Improve completion rate, reduce first-touch effort, and raise customer or staff confidence in the UX from the very first interaction.
- **EAI delivery:** Model the intake as tenant-isolated object types and resources, then use actions, chat workflows, and document indexing or classification to keep the initial record complete and usable.

### Step 2. Prepare the decision

- **Goal:** Turn the captured context into the next best action for Compliance Monitoring without forcing the human reviewer to assemble the case manually.
- **Required data:** Obligation state and history; Filing fields such as period, dueDate, submittedDate, and status.
- **AI support:** Run background summarisation, extraction, classification, recommendation drafting, and answer generation so a reviewer sees a prepared case instead of raw fragments. EAI delivers the structured records and AI workflow hooks for this today; specialised scoring engines, external rules, or advanced reasoning controls may still need integration work.
- **Business impact:** Reduce cycle time, improve quality and consistency, and protect the mission-critical metric before the case moves into execution.
- **EAI delivery:** Link records across the scenario, persist decision state as resources, and use workflow actions plus chat assistance to keep humans in control while AI prepares the work.

### Step 3. Execute and collaborate

- **Goal:** Coordinate the actual work, handoffs, approvals, and user updates needed to deliver the service or outcome.
- **Required data:** Filing actions such as submitFiling; AuditTrail fields such as action, user, timestamp, and details.
- **AI support:** Draft replies, produce work packets, monitor exceptions in the background, and surface the next action for each operator. EAI can orchestrate tenant-isolated records, actions, chats, and document workflows today; deeper system-to-system automation may require additional connectors or workflow capability.
- **Business impact:** Increase operator productivity, reduce rework across handoffs, and improve service consistency across the application journey.
- **EAI delivery:** Use linked object types, actions, resource updates, and workflow-triggered AI assistance so the team can execute in one model instead of splitting work across disconnected tools.

### Step 4. Resolve, explain, and improve

- **Goal:** Close the loop with a clear outcome, an understandable explanation, and feedback that improves the next case.
- **Required data:** final status, outcome, audit history, and follow-up signals across Obligation, Filing, and AuditTrail.
- **AI support:** Generate outcome summaries, customer-friendly answers, compliance-ready notes, management insights, and accessible follow-up content. EAI can store outcome records and support answer generation today, while richer proactive agents, advanced analytics, or channel-specific accessibility features may need additional product capability.
- **Business impact:** Increase trust, quality, and measurable business value through faster matter turnaround, stronger risk control, and higher knowledge reuse.
- **EAI delivery:** Keep the full audit trail in structured resources, use AI workflows to explain outcomes, and feed the resulting signals into future product, service, and operational improvement work.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Obligation** | `regulation` (text), `entity` (text), `description` (text), `frequency` (select: monthly, quarterly, semi-annual, annual, ad-hoc) | one-to-many → Filing | -- |
| **Filing** | `period` (text), `dueDate` (date), `submittedDate` (date), `status` (select: upcoming, in-progress, submitted, overdue) | many-to-one → Obligation, one-to-many → AuditTrail | `submitFiling` |
| **AuditTrail** | `action` (text), `user` (text), `timestamp` (date), `details` (text) | many-to-one → Filing | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init compliance-monitoring
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [Configuration](/docs/configuration) for login and local environment setup.
   </Aside>

3. **Define your Object Types**

   Create the Obligation, Filing, and AuditTrail types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: compliance-monitoring
   ✔ Obligation — 4 props, 1 link, 0 actions
   ✔ Filing — 4 props, 2 links, 1 action
   ✔ AuditTrail — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Obligation --data '{"regulation": "SEC Rule 17a-4", "entity": "US Broker-Dealer Division", "description": "Quarterly electronic records retention report", "frequency": "quarterly"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Code Example

```typescript
// src/eai.config/object-types.ts
export const objectTypes = {
  'compliance-monitoring': [
    {
      name: 'Obligation',
      displayName: 'Obligation',
      description: 'A regulatory obligation that requires periodic filings',
      properties: [
        { name: 'regulation', type: 'text' as const, required: true, indexed: true },
        { name: 'entity', type: 'text' as const, required: true, indexed: true },
        { name: 'description', type: 'text' as const, required: true },
        { name: 'frequency', type: 'select' as const, required: true, options: [
          { label: 'Monthly', value: 'monthly' },
          { label: 'Quarterly', value: 'quarterly' },
          { label: 'Semi-Annual', value: 'semi-annual' },
          { label: 'Annual', value: 'annual' },
          { label: 'Ad-Hoc', value: 'ad-hoc' },
        ]},
      ],
      linkTypes: [
        { name: 'filings', targetObjectType: 'Filing', cardinality: 'one-to-many' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
    {
      name: 'Filing',
      displayName: 'Filing',
      description: 'A specific filing instance for a regulatory obligation',
      properties: [
        { name: 'period', type: 'text' as const, required: true },
        { name: 'dueDate', type: 'date' as const, required: true, indexed: true },
        { name: 'submittedDate', type: 'date' as const, required: false },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'upcoming', options: [
          { label: 'Upcoming', value: 'upcoming' },
          { label: 'In Progress', value: 'in-progress' },
          { label: 'Submitted', value: 'submitted' },
          { label: 'Overdue', value: 'overdue' },
        ]},
      ],
      linkTypes: [
        { name: 'obligation', targetObjectType: 'Obligation', cardinality: 'many-to-one' as const },
        { name: 'auditTrail', targetObjectType: 'AuditTrail', cardinality: 'one-to-many' as const, cascadeDelete: true },
      ],
      actions: [
        {
          name: 'submitFiling',
          displayName: 'Submit Filing',
          description: 'Mark a filing as submitted to the regulatory body',
          requiredRole: 'tenant-staff',
          validationRules: { requiredStatus: 'in-progress' },
          sideEffects: [
            { type: 'set_field', field: 'status', value: 'submitted' },
            { type: 'set_timestamp', field: 'submittedDate' },
          ],
        },
      ],
      status: 'published' as const,
    },
    {
      name: 'AuditTrail',
      displayName: 'Audit Trail',
      description: 'An immutable record of an action taken on a filing',
      properties: [
        { name: 'action', type: 'text' as const, required: true },
        { name: 'user', type: 'text' as const, required: true },
        { name: 'timestamp', type: 'date' as const, required: true, indexed: true },
        { name: 'details', type: 'text' as const, required: false },
      ],
      linkTypes: [
        { name: 'filing', targetObjectType: 'Filing', cardinality: 'many-to-one' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
  ],
};
```

## Key Takeaways

- **Obligation catalog**: Every regulatory requirement is cataloged with its frequency and responsible entity, providing a complete compliance inventory.
- **Deadline-driven workflow**: Filings are indexed by due date, enabling dashboards that surface upcoming deadlines and overdue items at a glance.
- **Immutable audit trail**: Every action on a filing is recorded with the user and timestamp, creating regulator-ready evidence of compliance activities.
- **Multi-regulation support**: The obligation model supports different regulations and frequencies, scaling from a single filing requirement to hundreds across multiple regulatory frameworks.
