## Persona

**Role**: Logistics software engineer at a regional delivery company operating 40 vehicles across a metro area.

Dispatchers plan routes manually each morning by printing orders and grouping them by area on a physical map. Drivers receive paper route sheets, time windows are frequently missed because routes are not optimized for traffic or delivery priorities, and there is no real-time visibility into route progress. The company needs a digital route planning system.

## Business Problem

Manual route planning wastes driver time, fuel, and customer goodwill. Dispatchers spend two hours each morning building routes that an algorithm could generate in seconds. High-priority deliveries are not always scheduled first, time windows are violated because stop sequencing ignores travel time, and drivers have no way to report completion or delays digitally. This scenario builds a route optimization workflow that assigns stops to routes with time windows and priorities, tracks driver assignments, and monitors stop completion in real time.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Route** | `date` (date), `driver` (text), `vehicle` (text), `totalStops` (number), `distance` (number), `status` (select: planned, in-progress, completed) | one-to-many → Stop | `startRoute` |
| **Stop** | `address` (text), `timeWindow` (text), `priority` (select: standard, express, critical), `sequence` (number), `status` (select: pending, completed, failed, skipped) | many-to-one → Route | `completeStop` |
| **Driver** | `name` (text), `license` (text), `vehicle` (text), `availability` (select: available, on-route, off-duty) | one-to-many → Route | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init route-optimization
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [Configuration](/docs/configuration) and [Environment Profiles](/docs/profiles) for login and local environment setup.
   </Aside>

3. **Define your Object Types**

   Create the Route, Stop, and Driver types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: route-optimization
   ✔ Route — 6 props, 1 link, 1 action
   ✔ Stop — 5 props, 1 link, 1 action
   ✔ Driver — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Route --data '{"date": "2025-08-01", "driver": "Mike Torres", "vehicle": "Van-12", "totalStops": 18, "distance": 47.5, "status": "planned"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Structured stop sequencing**: Every stop has a sequence number and priority level, ensuring critical deliveries are handled first and routes are executed in order.
- **Real-time route progress**: Drivers complete stops digitally, giving dispatchers live visibility into which stops are done, pending, or failed.
- **Driver availability tracking**: Driver status (available, on-route, off-duty) enables dispatchers to assign routes based on current availability rather than guesswork.
- **Time window compliance**: Recording time windows on stops enables post-route analysis of on-time delivery performance for service level agreements.
