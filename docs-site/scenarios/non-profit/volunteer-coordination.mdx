## Persona

**Role**: Developer at a community organization with 300+ active volunteers supporting events and programs year-round.

Volunteer signups happen through email and paper forms. Shift assignments are managed in a shared calendar that only coordinators can access, and hours are self-reported on paper timesheets that are transcribed monthly. The organization cannot tell how many volunteer hours were contributed last year or which volunteers are most active.

## Business Problem

Volunteer engagement suffers when people sign up but never hear back, or when they arrive at an event with no clear assignment. Hour tracking is unreliable because self-reported paper timesheets are often submitted weeks late with estimated hours. Funders and board members ask for volunteer hour totals that take days to compile. This scenario builds a volunteer coordination workflow that maintains volunteer profiles with skills and availability, schedules shifts for events, and logs verified hours.

## Four-Step Application

This scenario works best as a four-step, human-in-the-loop application. The existing object model already gives this scenario a strong delivery backbone through Volunteer, Shift, and HourLog.

- **Mission metric focus:** greater mission reach, stronger stewardship, and better reporting quality.
- **Human + AI pattern:** Each step combines structured workflow data with chat assistance, background generation, document understanding, and accessible interaction patterns when they improve the experience.

### Step 1. Capture demand and context

- **Goal:** Make it easy for the user to start the Volunteer Coordination journey with complete, trusted context.
- **Required data:** Volunteer context such as name, skills, availability, and totalHours.
- **AI support:** Use chat to guide intake, generate clearer prompts, create accessible summaries, and assist with voice or vision-led capture when a form alone is not the best experience. EAI can support structured intake, chat workflows, and document-centred capture today; richer native multimodal capture may still need workflow extensions or connected services.
- **Business impact:** Improve completion rate, reduce first-touch effort, and raise customer or staff confidence in the UX from the very first interaction.
- **EAI delivery:** Model the intake as tenant-isolated object types and resources, then use actions, chat workflows, and document indexing or classification to keep the initial record complete and usable.

### Step 2. Prepare the decision

- **Goal:** Turn the captured context into the next best action for Volunteer Coordination without forcing the human reviewer to assemble the case manually.
- **Required data:** Volunteer state and history; Shift fields such as event, date, volunteersNeeded, and description.
- **AI support:** Run background summarisation, extraction, classification, recommendation drafting, and answer generation so a reviewer sees a prepared case instead of raw fragments. EAI delivers the structured records and AI workflow hooks for this today; specialised scoring engines, external rules, or advanced reasoning controls may still need integration work.
- **Business impact:** Reduce cycle time, improve quality and consistency, and protect the mission-critical metric before the case moves into execution.
- **EAI delivery:** Link records across the scenario, persist decision state as resources, and use workflow actions plus chat assistance to keep humans in control while AI prepares the work.

### Step 3. Execute and collaborate

- **Goal:** Coordinate the actual work, handoffs, approvals, and user updates needed to deliver the service or outcome.
- **Required data:** Shift actions such as completeShift; HourLog fields such as hours, supervisor, verified, and notes.
- **AI support:** Draft replies, produce work packets, monitor exceptions in the background, and surface the next action for each operator. EAI can orchestrate tenant-isolated records, actions, chats, and document workflows today; deeper system-to-system automation may require additional connectors or workflow capability.
- **Business impact:** Increase operator productivity, reduce rework across handoffs, and improve service consistency across the application journey.
- **EAI delivery:** Use linked object types, actions, resource updates, and workflow-triggered AI assistance so the team can execute in one model instead of splitting work across disconnected tools.

### Step 4. Resolve, explain, and improve

- **Goal:** Close the loop with a clear outcome, an understandable explanation, and feedback that improves the next case.
- **Required data:** final status, outcome, audit history, and follow-up signals across Volunteer, Shift, and HourLog.
- **AI support:** Generate outcome summaries, customer-friendly answers, compliance-ready notes, management insights, and accessible follow-up content. EAI can store outcome records and support answer generation today, while richer proactive agents, advanced analytics, or channel-specific accessibility features may need additional product capability.
- **Business impact:** Increase trust, quality, and measurable business value through greater mission reach, stronger stewardship, and better reporting quality.
- **EAI delivery:** Keep the full audit trail in structured resources, use AI workflows to explain outcomes, and feed the resulting signals into future product, service, and operational improvement work.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Volunteer** | `name` (text), `skills` (text), `availability` (text), `totalHours` (number), `status` (select: active, on-leave, alumni) | one-to-many → HourLog | -- |
| **Shift** | `event` (text), `date` (date), `volunteersNeeded` (number), `description` (text), `status` (select: open, filled, completed, cancelled) | one-to-many → HourLog | `completeShift` |
| **HourLog** | `hours` (number), `supervisor` (text), `verified` (boolean), `notes` (text), `loggedDate` (date) | many-to-one → Volunteer, many-to-one → Shift | `verifyHours` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init volunteer-coordination
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [Configuration](/docs/configuration) for login and local environment setup.
   </Aside>

3. **Define your Object Types**

   Create the Volunteer, Shift, and HourLog types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: volunteer-coordination
   ✔ Volunteer — 5 props, 1 link, 0 actions
   ✔ Shift — 5 props, 1 link, 1 action
   ✔ HourLog — 5 props, 2 links, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Volunteer --data '{"name": "Carlos Mendez", "skills": "Event setup, registration desk, first aid", "availability": "Weekends and evenings", "totalHours": 120, "status": "active"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Skills-based matching**: Volunteer profiles with skills and availability enable coordinators to match the right people to the right shifts.
- **Verified hour tracking**: Supervisor verification on hour logs replaces unreliable self-reported timesheets with accountable records.
- **Shift lifecycle management**: Shifts flow from open through filled to completed, giving coordinators visibility into staffing levels for upcoming events.
- **Aggregate reporting**: Linking hour logs to both volunteers and shifts enables reports by individual, event, or time period for funder and board reporting.
