The EAI CLI includes two diagnostic commands: `eai doctor` for comprehensive health checks with fix suggestions, and `eai verify` for connectivity testing. This guide covers both commands and provides solutions for the most common issues.

## Quick diagnosis

If something is not working, start here:

```bash
# Full diagnostic with fix suggestions
eai doctor

# Connectivity checks only
eai verify
```

## eai doctor

The `doctor` command performs a comprehensive health check of your project and suggests fixes for every issue it finds:

```bash
eai doctor
```

Output:

```
EAI Platform Health Check

✔ Project root: /Users/you/my-vertical
✔ .env.local exists
✔ BASE_URL_PUBLIC_API — set
✔ ENTRA_TENANT_ID — set
✗ AUTH_SECRET — not set
✔ Authenticated as user@example.com
✔ Object Types: 5 defined
⚠ deploy-demo.yml not found
✔ Dependencies installed
✔ Platform SDK present

3 issue(s) found

✗ AUTH_SECRET not set or has placeholder value
  Fix: Set AUTH_SECRET in .env.local or run `eai env pull --include-secrets`
⚠ deploy-demo.yml not found
  Fix: Run `eai deploy setup` to generate the workflow
```

### What doctor checks

| Check                       | What it verifies                                     |
|-----------------------------|------------------------------------------------------|
| Project root                | An EAI project is detected in the current directory  |
| `.env.local` exists         | The environment file is present                      |
| Required environment vars   | `BASE_URL_PUBLIC_API`, `ENTRA_TENANT_ID`, `AUTH_SECRET` |
| Authentication              | A valid (non-expired) token exists                   |
| Object Types                | `object-types.ts` loads without errors               |
| Deployment workflow         | `.github/workflows/deploy-demo.yml` exists           |
| Dependencies                | `node_modules` directory exists                      |
| Platform SDK                | Local `packages/platform-sdk` is present             |

## eai verify

The `verify` command tests live connectivity to the platform services:

```bash
eai verify
```

Output:

```
Platform Connectivity Checks

✔ PublicAPI reachable (142ms)
✔ Authenticated as user@example.com
✔ Platform service reachable
✔ Data service reachable — 5 published types
✔ Local Object Types: 5 types across 2 tenant scope(s)

All 5 checks passed
```

### What verify checks

| Check                | What it tests                                        |
|----------------------|------------------------------------------------------|
| PublicAPI gateway    | HTTP request to the API `/health` endpoint           |
| Authentication       | Token is present and not expired                     |
| Platform service     | Can reach the platform service via `/v3/orchestrate` |
| Data service         | Can fetch the schema via `/v3/resources/schema`      |
| Local Object Types   | Can load `object-types.ts` from the project          |

## Common issues

### Not in an EAI project

**Error:**
```
✗ Not in an EAI project.
```

**Cause:** The CLI cannot find an EAI project root. It looks for:
- `eai.config.ts` in the current or parent directories
- `src/eai.config/object-types.ts`
- `package.json` with `@enterpriseaigroup/platform-sdk`, legacy `@eai-tools/platform-sdk`, or `@eai-tools/core` as a dependency

**Fix:**
```bash
# Navigate to your project directory
cd /path/to/my-vertical

# Or create a new project
eai init my-vertical
```

### Missing environment variables

**Error:**
```
✗ Missing BASE_URL_PUBLIC_API or tenant ID.
```

**Cause:** The `.env.local` file is missing or does not contain the required variables.

**Fix:**
```bash
# Pull configuration from Azure App Config
eai env pull --include-secrets

# Verify the variables are set
eai env list
```

### Authentication failures

<Tabs>
  <TabItem label="Not authenticated">
    **Error:**
    ```
    ⚠ Not authenticated — run `eai login`
    ```

    **Fix:**
    ```bash
    eai login
    ```
  </TabItem>
  <TabItem label="Token expired">
    **Error:**
    ```
    401 Unauthorized
    ```

    **Cause:** Your access token has expired and the refresh token is also invalid.

    **Fix:**
    ```bash
    eai logout
    eai login
    ```
  </TabItem>
  <TabItem label="Tenant mismatch">
    **Error:**
    ```
    Authentication failed: ...
    ```

    **Fix:**
    ```bash
    # Verify the target tenant values
    eai env list

    # Or login explicitly against the correct tenant
    eai login --tenant-name yourorg --tenant-id 12345678-abcd-efgh-ijkl-123456789012
    ```
  </TabItem>
  <TabItem label="Redirect URI mismatch">
    **Error:**
    ```
    AADSTS50011: The redirect URI 'http://localhost:3000' specified in the request
    does not match the redirect URIs configured for the application.
    ```

    **Cause:** The app registration does not have `http://localhost:3000` (or your custom port) listed as a redirect URI. This affects both the browser login in the web app and the CLI's localhost callback during `eai login`.

    **Fix:** Add the localhost URI to your app registration. See [Local Development](/eai-cli/guides/local-development/) for step-by-step instructions. If you do not have Azure Portal access, ask your platform admin to add the redirect URI.
  </TabItem>
  <TabItem label="Browser callback timeout">
    **Error:**
    ```
    ✗ Timed out waiting for browser authentication callback.
    ```

    **Cause:** You did not complete the browser authentication within the time limit, or the browser could not return to the CLI's localhost callback.

    **Fix:** Run `eai login` again and complete the browser step promptly.
  </TabItem>
</Tabs>

### Azure CLI not found

**Error:**
```
✗ Azure CLI not found or not logged in. Run `az login` first.
```

**Cause:** The `eai env pull` and `eai env push` commands require the Azure CLI.

**Fix:**
```bash
# Install Azure CLI
brew install azure-cli    # macOS
# or
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash  # Linux

# Log in
az login
```

### Key Vault access denied

**Error:**
```
⚠ AUTH_SECRET — Key Vault access denied
```

**Cause:** Your Azure identity does not have access to the Key Vault where secrets are stored.

**Fix:** Contact your platform administrator to grant Key Vault access, or use the non-secret values only:

```bash
# Pull without secrets
eai env pull

# Ask an admin to provide the secrets separately
```

### Object Types validation errors

**Error:**
```
✗ InspectionReport
    error: name "inspectionReport" must be PascalCase
    error: select property "severity" must have options
```

**Cause:** Your Object Type definitions in `object-types.ts` do not pass validation.

**Fix:** Edit `src/eai.config/object-types.ts` and address each error:

```typescript
// Fix: PascalCase name
name: 'InspectionReport',  // not 'inspectionReport'

// Fix: Add options to select
{
  name: 'severity',
  type: 'select',
  required: true,
  options: [
    { label: 'Low', value: 'low' },
    { label: 'High', value: 'high' },
  ],
}
```

Then re-validate:

```bash
eai types validate
```

### Platform API connectivity issues

**Error:**
```
✗ PublicAPI not reachable: fetch failed
```

**Cause:** The `BASE_URL_PUBLIC_API` is incorrect, the service is down, or there is a network issue.

**Fix:**
<Steps>
1. Check the URL is correct:
   ```bash
   eai env list | grep BASE_URL_PUBLIC_API
   ```

2. Test connectivity manually:
   ```bash
   curl -s -o /dev/null -w "%{http_code}" "${BASE_URL_PUBLIC_API}/health"
   ```

3. If behind a VPN, verify your VPN connection is active.

4. If the URL is wrong, update it:
   ```bash
   eai env pull
   ```
</Steps>

### Deployment failures

**Error:**
```
✗ Could not detect GitHub repo. Use --repo org/name
```

**Cause:** The CLI cannot determine your GitHub repository from the git remote.

**Fix:**
```bash
# Check your git remote
git remote -v

# Specify the repo explicitly
eai deploy trigger --repo your-org/your-repo
eai deploy status --repo your-org/your-repo
```

### Version conflict on update

**Error:**
```
✗ 409 Conflict
```

**Cause:** Another user or process updated the resource since you last read it. The version number does not match.

**Fix:** Fetch the latest version and retry:

```bash
# Get the current version
eai resources get Patient <id> --format json | jq '.version'

# Update with the correct version
eai resources update Patient <id> --data '{"status": "active"}' --version <current-version>
```

## Debug mode

For more detailed output when troubleshooting, set the `DEBUG` environment variable:

```bash
DEBUG=eai:* eai resources list Patient
```

This shows additional request/response details for debugging API calls.

## Common issues quick reference

| Error                                        | Cause                              | Fix                                  |
|----------------------------------------------|------------------------------------|--------------------------------------|
| Not in an EAI project                        | Wrong directory                    | `cd` to project or `eai init`        |
| Missing BASE_URL_PUBLIC_API                  | No `.env.local`                    | `eai env pull`                       |
| 401 Unauthorized                             | Token expired                      | `eai logout && eai login`            |
| Azure CLI not found                          | `az` not installed                 | `brew install azure-cli`             |
| Key Vault access denied                      | Missing RBAC permissions           | Contact platform admin               |
| Object Type name must be PascalCase          | Invalid naming                     | Rename to `PascalCase`               |
| PublicAPI not reachable                       | Network or URL issue               | Check VPN, verify URL                |
| 409 Conflict                                 | Optimistic locking version mismatch| Refetch and retry with correct version |
| AADSTS50011 redirect URI mismatch            | Localhost not registered           | Add redirect URI ([guide](/eai-cli/guides/local-development/)) |
| Browser sign-in timed out                    | Browser auth not completed in time | Re-run `eai login`                   |
| deploy-demo.yml not found                    | Workflow not generated             | `eai deploy setup`                   |
| node_modules not found                       | Dependencies not installed         | `npm install`                        |

If the built-in diagnostics do not resolve your issue:
