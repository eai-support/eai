The EAI platform is multi-tenant by design. Every resource, Object Type, and user belongs to a tenant. Data is fully isolated between tenants -- a user in Tenant A never sees resources from Tenant B. The `eai tenant` command lets you create, list, and inspect tenants from the terminal.

## How it works

```
Tenant (parent)
  ├── Tenant (child A)
  │     ├── Object Types
  │     ├── Resources
  │     └── Users
  └── Tenant (child B)
        ├── Object Types
        ├── Resources
        └── Users
```

Tenants form a hierarchy. A parent tenant can have child tenants, each with their own isolated data. This supports scenarios like a franchise model (parent company with regional tenants) or a SaaS platform (each customer gets their own tenant).

## Listing tenants

View all active tenants where you are a `tenant-admin`:

```bash
eai tenant list
```

Output:

```
✔ 4 tenant-admin memberships
→ acme-corp — Acme Corp (acme.example.com) [tenant-admin]
→ acme-west — Acme West [tenant-admin]
→ acme-east — Acme East [tenant-admin]
→ acme-south — Acme South [tenant-admin]
```

`eai tenant list` is intentionally filtered. It does not return every tenant membership for the logged-in user; it only returns tenants where that user has the `tenant-admin` role.

## Selecting the active tenant

Platform commands use the active tenant stored in your CLI login context, not a tenant ID from `.env.local`.

```bash
eai login
eai tenant select
```

If you have a single active tenant-admin membership, the CLI selects it automatically after login. If you have multiple memberships, `eai tenant select` lets you choose the tenant to work with now, similar to selecting a subscription in Azure CLI.

### Filter by parent

List only child tenants of a specific parent, still restricted to your tenant-admin memberships:

```bash
eai tenant list --parent abc12345-def6-7890-abcd-ef0123456789
```

### JSON output

```bash
eai tenant list --format json
```

```json
{
  "tenants": [
    {
      "id": "abc12345-def6-7890-abcd-ef0123456789",
      "displayName": "Acme Corp",
      "slug": "acme-corp",
      "domain": "acme.example.com",
      "isActive": true,
      "roles": ["tenant-admin"]
    }
  ],
  "count": 1
}
```

## Getting tenant details

View full details for a specific tenant:

```bash
eai tenant info abc12345-def6-7890-abcd-ef0123456789
```

Output:

```
✔ Tenant: Acme Corp
{
  "id": "abc12345-def6-7890-abcd-ef0123456789",
  "name": "Acme Corp",
  "slug": "acme-corp",
  "domain": ["acme.example.com"],
  "parent": null,
  "created_at": "2025-01-01T00:00:00Z"
}
```

## Creating a tenant

Create a new tenant with a name and slug:

```bash
eai tenant create --name "Acme West Region" --slug acme-west
```

Output:

```
✔ Created tenant acme-west (111aaaa-222b-333c-444d-555eee666fff)
```

### Child tenants

Create a tenant as a child of an existing parent:

```bash
eai tenant create \
  --name "Acme West Region" \
  --slug acme-west \
  --parent abc12345-def6-7890-abcd-ef0123456789
```

### Domains

Associate one or more domains with a tenant:

```bash
eai tenant create \
  --name "Acme Corp" \
  --slug acme-corp \
  --domain "acme.example.com,acme-portal.example.com"
```

Domains are used for routing -- the platform can determine which tenant a request belongs to based on the domain of the incoming request.

<Aside type="note">
  Tenant slugs must be kebab-case (lowercase with hyphens). The slug is used as an identifier in URLs and configuration.
</Aside>

## Data isolation

Every API call is scoped to a tenant. When you run CLI commands, the tenant comes from your active login selection:

- `eai resources *`
- `eai docs *`
- `eai chat *`
- `eai types diff`
- `eai types seed`
- `eai verify`

Resources created under one tenant are invisible to other tenants.

```
Tenant A                    Tenant B
┌─────────────────┐        ┌─────────────────┐
│ Patient: Jane   │        │ Patient: Bob    │
│ Patient: John   │        │ Patient: Alice  │
│                 │        │                 │
│ (invisible to B)│        │ (invisible to A)│
└─────────────────┘        └─────────────────┘
```

## Tenant hierarchy

Parent-child tenant relationships support organizational structures:

```
Enterprise (root tenant)
  ├── Division A
  │     ├── Team A1
  │     └── Team A2
  └── Division B
        ├── Team B1
        └── Team B2
```

Each level in the hierarchy has its own isolated data. A parent tenant administrator can manage child tenants, but a child tenant user cannot access sibling tenant data.

### Creating a hierarchy

<Steps>
1. **Create the parent tenant:**

   ```bash
   eai tenant create --name "Enterprise" --slug enterprise
   ```

2. **Create child tenants under the parent:**

   ```bash
   eai tenant create \
     --name "Division A" \
     --slug division-a \
     --parent <enterprise-tenant-id>

   eai tenant create \
     --name "Division B" \
     --slug division-b \
     --parent <enterprise-tenant-id>
   ```

3. **Create further nested children:**

   ```bash
   eai tenant create \
     --name "Team A1" \
     --slug team-a1 \
     --parent <division-a-tenant-id>
   ```
</Steps>

## Local object-type scopes

Your project can still define multiple local scopes in `object-types.ts`:

```typescript title="src/eai.config/object-types.ts"
export const objectTypes: Record<string, ObjectTypeDefinition[]> = {
  'division-a': [
    // Object Types for Division A
    { name: 'Project', /* ... */ },
  ],
  'division-b': [
    // Object Types for Division B
    { name: 'WorkOrder', /* ... */ },
  ],
};
```

When you run `eai types seed` or `eai types diff`, the CLI:

- chooses the remote platform tenant from your active login selection
- chooses the local object-type scope from `--tenant-key`, an active-tenant slug match, `template`, `default`, or an interactive prompt

Use `--tenant-id <uuid>` only when you intentionally want to override the active tenant for a one-off publish or diff run.

## Domains

Domains are used for request routing in multi-tenant applications. When a user visits `acme.example.com`, the platform routes the request to the Acme tenant.

### Associating domains during creation

```bash
eai tenant create \
  --name "Acme Corp" \
  --slug acme-corp \
  --domain "acme.example.com,portal.acme.com"
```

### Viewing tenant domains

```bash
eai tenant list
```

```
  acme-corp abc12345-def6-7890-abcd-ef0123456789
    domains: acme.example.com, portal.acme.com
```

## Working with multiple tenants in the CLI

You can switch between tenants with:

```bash
eai tenant select
```

For Object Type operations, use the `--tenant-key` flag:

```bash
# Seed types for a specific tenant only
eai types seed --tenant-key division-a
```

## Command reference

| Command                  | Description                              |
|--------------------------|------------------------------------------|
| `eai tenant list`        | List active tenant-admin memberships     |
| `eai tenant info <id>`   | Show details for a specific tenant       |
| `eai tenant create`      | Create a new tenant                      |

### Flags

| Flag               | Command   | Description                              |
|--------------------|-----------|------------------------------------------|
| `--parent <id>`    | `list`, `create` | Parent tenant ID for filtering or hierarchy |
| `--format <format>` | `list`   | Output format (`text` or `json`)         |
| `--json`           | `list`    | Legacy alias for `--format json`         |
| `--name <name>`    | `create`  | **(required)** Tenant display name       |
| `--slug <slug>`    | `create`  | **(required)** Tenant slug (kebab-case)  |
| `--domain <list>`  | `create`  | Comma-separated list of domains          |
