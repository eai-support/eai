Resources are instances of your [Object Types](/eai-cli/guides/object-types/). If an Object Type is "Patient", then a resource is a specific patient record. The `eai resources` command gives you full CRUD operations, querying, filtering, and cross-type queries from the terminal.

## How it works

```
eai resources create Patient --data '{...}'
                 │
                 ▼
         Platform API (/v3/resources)
                 │
                 ▼
       Resource stored with tenant isolation
```

The CLI reads your `BASE_URL_PUBLIC_API` and tenant ID from `.env.local`, attaches your Bearer token, and calls the Platform API. Every resource is scoped to a tenant -- you never see resources from other tenants.

## Creating resources

Create a resource by specifying the Object Type name and providing data as JSON:

```bash
eai resources create Patient --data '{
  "firstName": "Jane",
  "lastName": "Doe",
  "dateOfBirth": "1990-03-15",
  "email": "jane.doe@example.com",
  "status": "active"
}'
```

You can also load data from a file:

```bash
eai resources create Patient --file ./data/patient.json
```

```json title="data/patient.json"
{
  "firstName": "Jane",
  "lastName": "Doe",
  "dateOfBirth": "1990-03-15",
  "email": "jane.doe@example.com",
  "status": "active"
}
```

The CLI returns the created resource ID on success:

```
✔ Created Patient 3f8a2b1c
```

## Listing resources

List all resources of a given type:

```bash
eai resources list Patient
```

Output:

```
✔ 47 total — page 1/3
  3f8a2b1c firstName=Jane, lastName=Doe, status=active
  a1b2c3d4 firstName=John, lastName=Smith, status=active
  ...
```

### Pagination

Control page size and page number:

```bash
# Show 50 items per page
eai resources list Patient --limit 50

# Go to page 2
eai resources list Patient --page 2 --limit 50
```

### Sorting

Sort by any field. Prefix with `-` for descending order:

```bash
# Sort by creation date, newest first (default)
eai resources list Patient --sort -created_at

# Sort by last name, ascending
eai resources list Patient --sort lastName

# Sort by status descending
eai resources list Patient --sort -status
```

### JSON output

Get raw JSON for piping to other tools:

```bash
eai resources list Patient --json
```

```json
{
  "docs": [
    {
      "id": "3f8a2b1c-...",
      "data": {
        "firstName": "Jane",
        "lastName": "Doe",
        "status": "active"
      },
      "created_at": "2025-01-15T10:30:00Z",
      "version": 1
    }
  ],
  "totalDocs": 47,
  "page": 1,
  "totalPages": 3
}
```

<Aside type="tip">
  Combine `--json` with tools like `jq` for powerful filtering: `eai resources list Patient --json | jq '.docs[] | .data.email'`
</Aside>

## Getting a single resource

Fetch a resource by its type and ID:

```bash
eai resources get Patient 3f8a2b1c-1234-5678-abcd-ef0123456789
```

Add `--json` for raw output:

```bash
eai resources get Patient 3f8a2b1c-1234-5678-abcd-ef0123456789 --json
```

## Updating resources

Update specific fields on an existing resource:

```bash
eai resources update Patient 3f8a2b1c-1234-5678-abcd-ef0123456789 \
  --data '{"email": "jane.new@example.com"}'
```

### Optimistic locking

Resources use version-based optimistic locking. By default, the CLI fetches the current version automatically before updating. You can specify the version explicitly to guard against concurrent edits:

```bash
eai resources update Patient 3f8a2b1c --data '{"status": "inactive"}' --version 3
```

If the version does not match the current version on the platform, the update is rejected. This prevents one user from overwriting another user's changes.

## Deleting resources

Delete a resource by type and ID:

```bash
eai resources delete Patient 3f8a2b1c-1234-5678-abcd-ef0123456789
```

The CLI prompts for confirmation. Use `--force` to skip the prompt (useful in scripts):

```bash
eai resources delete Patient 3f8a2b1c --force
```

<Aside type="caution">
  Deletion is permanent. If the Object Type has links with `cascadeDelete: true`, linked resources will also be deleted.
</Aside>

## Cross-type queries

Query across multiple Object Types at once using `eai resources query`:

```bash
eai resources query --types Patient,Appointment --limit 10
```

### Filtering with --where

Pass filter conditions as a JSON object:

```bash
eai resources query \
  --types Patient \
  --where '{"status": {"equals": "active"}}'
```

Supported filter operators:

| Operator        | Example                                    | Description           |
|-----------------|--------------------------------------------|-----------------------|
| `equals`        | `{"status": {"equals": "active"}}`         | Exact match           |
| `not_equals`    | `{"status": {"not_equals": "inactive"}}`   | Not equal             |
| `contains`      | `{"name": {"contains": "doe"}}`            | Substring match       |
| `greater_than`  | `{"age": {"greater_than": 18}}`            | Numeric comparison    |
| `less_than`     | `{"age": {"less_than": 65}}`               | Numeric comparison    |

### Combining filters

```bash
eai resources query \
  --types InspectionReport \
  --where '{
    "severity": {"equals": "critical"},
    "status": {"equals": "submitted"}
  }' \
  --limit 50
```

## Viewing the schema

See all published Object Types for your tenant:

```bash
eai resources schema
```

Output:

```
✔ 5 published types
  Patient — 8 props, 2 links, 3 actions
  Appointment — 5 props, 1 links, 2 actions
  Physician — 4 props, 0 links, 0 actions
  InsurancePlan — 6 props, 0 links, 1 actions
  Contact — 3 props, 0 links, 0 actions
```

## Executing actions

Actions defined on Object Types can be executed via the Platform API. While the CLI does not currently expose a dedicated `eai resources action` subcommand, you can call actions through the API:

```bash
curl -X POST "${BASE_URL_PUBLIC_API}/v3/resources/${TENANT_ID}/Patient/${RESOURCE_ID}/actions/submit" \
  -H "Authorization: Bearer $(eai whoami --token)" \
  -H "Content-Type: application/json" \
  -d '{"params": {}}'
```

<Aside type="note">
  Action execution respects the `requiredRole` and `validationRules` defined on the Object Type. If the acting user lacks the required role or validation fails, the action is rejected.
</Aside>

## Common workflows

### Bulk creation from a directory of JSON files

```bash
for file in data/patients/*.json; do
  eai resources create Patient --file "$file"
done
```

### Export all resources to a file

```bash
eai resources list Patient --limit 1000 --json > patients-export.json
```

### Filter and count

```bash
eai resources query \
  --types Patient \
  --where '{"status": {"equals": "active"}}' \
  --json | jq '.docs | length'
```

| `eai resources delete <type> <id>` | Delete a resource                |
