When you run `eai dev`, the CLI starts a local Next.js development server. The CLI itself authenticates via device code flow (no redirect URI needed), but the **web application** running in the browser uses a redirect-based authentication flow that requires localhost to be registered as a redirect URI in your Azure app registration.

## Two authentication flows

| Flow | Used by | Redirect URI needed? |
|------|---------|---------------------|
| **Device code** | CLI (`eai login`) | No — user enters a code in the browser manually |
| **SPA redirect** | Web app (`eai dev`, browser) | Yes — browser redirects back to `http://localhost:3000` after login |

If localhost is not registered as a redirect URI, the web app will show a Microsoft error page when a user tries to sign in from the browser.

## Adding localhost redirect URIs

<Aside type="tip">
  If you do not have access to the Azure Portal, skip to [Ask your platform admin](#ask-your-platform-admin) below.
</Aside>

<Steps>

1. **Open the Azure Portal** and navigate to **Microsoft Entra ID** > **App registrations**.

2. **Select your app registration** — this is the app registration for the vertical's web application (not the CLI app registration used by `eai login`).

3. Go to **Authentication** > **Platform configurations** > **Single-page application**.

4. **Add redirect URIs**:

   ```
   http://localhost:3000
   ```

   If you use a custom port with `eai dev --port`, add that too:

   ```
   http://localhost:4000
   ```

5. **Save** the configuration.

</Steps>

<Aside type="caution">
  Keep your production redirect URI (e.g., `https://app.yourorg.ai`) alongside the localhost URI. Do not remove it when adding localhost.
</Aside>

## Custom ports

The default port for `eai dev` is `3000`. If you run on a different port:

```bash
eai dev --port 4000
```

You must register `http://localhost:4000` as an additional redirect URI. Each port requires its own entry — `http://localhost:3000` does not cover `http://localhost:4000`.

## Common error

If localhost is not registered, Microsoft Entra ID returns:

```
AADSTS50011: The redirect URI 'http://localhost:3000' specified in the request
does not match the redirect URIs configured for the application.
```

**Fix:** Add the exact URI shown in the error message to your app registration's redirect URIs (see steps above).

## Ask your platform admin

If you do not have access to the Azure Portal to modify app registrations, ask your platform administrator to:

1. Add `http://localhost:3000` as a **Single-page application** redirect URI on the vertical's app registration
2. Add any custom ports you need (e.g., `http://localhost:4000`)
3. Confirm that the app registration's **Supported account types** includes your directory

Provide them with the exact `AADSTS50011` error message if you have one — it contains the redirect URI that needs to be registered.
