In this guide, you will build a **Task Manager** vertical application with three Object Types -- Project, Task, and Comment. By the end, you will have a working data model with typed properties, relationships between types, and actions with side effects, all published to the EnterpriseAI platform.

This tutorial assumes you have already completed the [Quick Start](/eai-cli/getting-started/quickstart/) and are authenticated with `eai login`.

## What you will build

The Task Manager has three interconnected types:

- **Project** -- a container for tasks, with a name, description, and status
- **Task** -- a work item belonging to a project, with priority, assignment, and lifecycle actions
- **Comment** -- a note attached to a task, with author tracking and timestamps

These types are connected through relationships: a Project has many Tasks, and a Task has many Comments.

### Understanding the structure

Each Object Type has four main sections:

**Properties** define the fields on each resource. Each property has a `name`, a `type`, and optional attributes like `required`, `indexed`, and `defaultValue`. The available field types are:

| Type | Use case | Example |
|------|----------|---------|
| `text` | Strings -- names, descriptions, IDs | Task title, comment body |
| `number` | Integers or floats | Priority level, count |
| `boolean` | True/false flags | `isBlocked`, `isInternal` |
| `date` | ISO 8601 timestamps | `startedAt`, `completedAt` |
| `select` | Enum values with predefined options | Status field |
| `json` | Arbitrary structured data | Tags, metadata |
| `file` | File reference URLs | Attachments |
| `relationship` | Reference to another resource by ID | `projectId`, `assignedTo` |

**Link types** define relationships between Object Types. Each link has a `targetObjectType` and a `cardinality`:

| Cardinality | Meaning | Example |
|-------------|---------|---------|
| `one-to-many` | Parent has many children | Project has many Tasks |
| `many-to-one` | Child points to one parent | Task belongs to one Project |
| `one-to-one` | Single reference in each direction | Profile belongs to one User |
| `many-to-many` | Bidirectional collection | Tags on articles |

Setting `cascadeDelete: true` means that when the parent is deleted, all linked children are also deleted. In our model, deleting a Project deletes its Tasks, and deleting a Task deletes its Comments.

**Actions** define named operations with role requirements and side effects. When a user triggers an action:
1. The platform checks whether the user has the `requiredRole` (`tenant-user`, `tenant-staff`, or `tenant-admin`)
2. It validates the `validationRules` (required fields, required current status)
3. It executes the `sideEffects` in order

The three side effect types are:

| Side effect | What it does |
|-------------|-------------|
| `set_field` | Sets a property to a specific value |
| `set_timestamp` | Sets a date property to the current time |
| `set_user` | Sets a relationship property to the current user's ID |

## Validate the types

Run the validator to catch errors before pushing to the platform:

```bash
eai types validate
```

```
Tenant: task-manager
✔ Project — 8 props, 1 links, 1 actions
✔ Task — 11 props, 2 links, 3 actions
✔ Comment — 6 props, 1 links, 0 actions

✔ All Object Types are valid
```

The validator checks for:
- PascalCase naming on type names
- Required `displayName` on each type
- Valid property types and `select` options
- Valid link cardinality values
- Valid action roles and side effect types
- References to existing properties in side effects

## Seed to the platform

Push your validated types to the platform:

```bash
eai types seed
```

```
✔ Found 3 types across 1 tenant scope(s): task-manager

Tenant: task-manager → abc123-def456
  ✔ Project (created)
  ✔ Task (created)
  ✔ Comment (created)

Result: 3 created, 0 updated, 0 failed
```

If you run `eai types seed` again later after making changes, existing types are updated rather than duplicated.

<Aside type="tip">
  Use `eai types seed --dry-run` to preview what would be seeded without making any changes to the platform.
</Aside>

## Create resources

Now that your types are published, you can create resources from the command line.

### Create a project

```bash
eai resources create Project --data '{
  "name": "Website Redesign",
  "description": "Redesign the company website with new branding",
  "status": "active",
  "owner": "user-001"
}'
```

```
✔ Created Project a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

### Create tasks in the project

```bash
eai resources create Task --data '{
  "title": "Design homepage mockup",
  "description": "Create wireframes and high-fidelity mockups for the new homepage",
  "status": "open",
  "priority": 1,
  "projectId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "dueDate": "2026-04-01T00:00:00Z"
}'
```

```
✔ Created Task f1e2d3c4-b5a6-7890-abcd-ef1234567890
```

```bash
eai resources create Task --data '{
  "title": "Write content for About page",
  "status": "open",
  "priority": 3,
  "projectId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}'
```

### Add a comment to a task

```bash
eai resources create Comment --data '{
  "body": "The mockup looks great. Let us move to development.",
  "author": "user-002",
  "taskId": "f1e2d3c4-b5a6-7890-abcd-ef1234567890"
}'
```

## Query resources

### List all tasks

```bash
eai resources list Task
```

```
✔ 2 total — page 1/1
  a1b2c3d4 title=Design homepage mockup, status=open, priority=1
  f1e2d3c4 title=Write content for About page, status=open, priority=3
```

### Get a single resource

```bash
eai resources get Task f1e2d3c4-b5a6-7890-abcd-ef1234567890
```

### Cross-type query

Query across multiple Object Types at once:

```bash
eai resources query --types Task,Comment --where '{"status": {"equals": "open"}}' --limit 10
```

See all Object Types currently published for your tenant:

```bash
eai types diff
```

```

  ✔ Fetching remote types...
```

This shows you exactly which properties, links, or types exist only locally or only on the platform, before you run `eai types seed` to apply the changes.

## Start developing

With your types seeded and sample data created, start the local dev server:

```bash
eai dev
```

Your vertical application is now running locally with live data from the platform. The Vertical Template includes a UI that automatically renders pages for your Object Types, so you can start building custom views and workflows immediately.
