## Persona

**Role**: Grants management developer at a non-profit managing 25 active grants totaling $4M in annual funding.

The grants team tracks deliverables in individual spreadsheets per funder, stores compliance documentation in shared folders organized by grant name, and compiles reports manually before each deadline. When a funder changes reporting requirements, the team scrambles to adapt because there is no centralized view of what is owed, to whom, and by when.

## Business Problem

Missing a grant reporting deadline or failing a compliance check can result in funding clawbacks and damaged funder relationships. Each grant has unique milestones, reporting frequencies, and compliance requirements that are tracked in isolation. The grants team cannot see which milestones are coming due across all grants, and compliance evidence is scattered. This scenario builds a grant reporting workflow that tracks milestones with evidence, monitors compliance requirements, and provides a unified view of reporting obligations across all funders.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Grant** | `funder` (text), `amount` (number), `purpose` (text), `startDate` (date), `endDate` (date), `status` (select: pending, active, closed, suspended) | one-to-many → Milestone, one-to-many → ComplianceCheck | `activateGrant` |
| **Milestone** | `description` (text), `dueDate` (date), `evidence` (text), `status` (select: upcoming, in-progress, completed, overdue) | many-to-one → Grant | `completeMilestone` |
| **ComplianceCheck** | `requirement` (text), `notes` (text), `checkedDate` (date), `status` (select: compliant, non-compliant, pending-review) | many-to-one → Grant | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init grant-reporting
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Grant, Milestone, and ComplianceCheck types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: grant-reporting
   ✔ Grant — 6 props, 2 links, 1 action
   ✔ Milestone — 4 props, 1 link, 1 action
   ✔ ComplianceCheck — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Grant --data '{"funder": "Ford Foundation", "amount": 500000, "purpose": "Community health worker training program", "startDate": "2025-01-01", "endDate": "2027-12-31", "status": "active"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Cross-grant visibility**: All milestones across all grants are indexed by due date, providing a single view of upcoming deliverables regardless of funder.
- **Evidence-based completion**: Milestones require evidence documentation before they can be marked complete, ensuring the grants team has supporting materials ready for funder review.
- **Compliance monitoring**: Ongoing compliance checks are linked to their grant, making it easy to demonstrate adherence to funder requirements during audits.
- **Grant lifecycle management**: The structured status flow from pending through active to closed tracks each grant from award notification through closeout.
