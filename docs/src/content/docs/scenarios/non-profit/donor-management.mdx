## Persona

**Role**: Developer at a mid-size non-profit with 5,000+ donors and an annual fundraising goal of $2M.

The development team tracks donors in a legacy database, processes donations through a separate payment system, and manages campaigns in spreadsheets. Donor engagement history is fragmented, making it impossible to identify lapsed donors, calculate lifetime giving, or measure campaign effectiveness. The organization needs a unified donor management system.

## Business Problem

Donor retention is the lifeblood of sustainable fundraising, but the organization cannot identify which donors are at risk of lapsing because giving history is spread across multiple systems. Campaign performance is evaluated weeks after completion because donation data must be manually reconciled. Major gift officers lack a complete picture of a donor's history when preparing for cultivation meetings. This scenario builds a donor management workflow that maintains donor profiles with giving history, tracks individual donations linked to campaigns, and measures campaign performance in real time.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Donor** | `name` (text), `contact` (text), `totalGiving` (number), `firstGiftDate` (date), `status` (select: active, lapsed, major, prospect) | one-to-many → Donation | -- |
| **Donation** | `amount` (number), `campaign` (text), `date` (date), `method` (select: online, check, wire, in-kind), `acknowledged` (boolean) | many-to-one → Donor | `acknowledgeDonation` |
| **Campaign** | `name` (text), `goal` (number), `raised` (number), `startDate` (date), `endDate` (date), `status` (select: planning, active, completed) | -- | `launchCampaign` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init donor-management
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Donor, Donation, and Campaign types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: donor-management
   ✔ Donor — 5 props, 1 link, 0 actions
   ✔ Donation — 5 props, 1 link, 1 action
   ✔ Campaign — 6 props, 0 links, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Donor --data '{"name": "Elizabeth Warren", "contact": "e.warren@email.com", "totalGiving": 15000, "firstGiftDate": "2020-12-15", "status": "major"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Lifetime giving visibility**: Donor profiles with total giving and first gift date enable segmentation by giving level and identification of lapsed donors.
- **Campaign performance tracking**: Linking donations to campaigns with goal and raised amounts provides real-time visibility into fundraising progress.
- **Acknowledgment workflow**: The `acknowledgeDonation` action ensures every gift receives a thank-you, a critical practice for donor retention.
- **Donor segmentation**: Status categories (active, lapsed, major, prospect) enable targeted outreach strategies for different donor populations.
