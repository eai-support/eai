## Persona

**Role**: Developer at a community organization with 300+ active volunteers supporting events and programs year-round.

Volunteer signups happen through email and paper forms. Shift assignments are managed in a shared calendar that only coordinators can access, and hours are self-reported on paper timesheets that are transcribed monthly. The organization cannot tell how many volunteer hours were contributed last year or which volunteers are most active.

## Business Problem

Volunteer engagement suffers when people sign up but never hear back, or when they arrive at an event with no clear assignment. Hour tracking is unreliable because self-reported paper timesheets are often submitted weeks late with estimated hours. Funders and board members ask for volunteer hour totals that take days to compile. This scenario builds a volunteer coordination workflow that maintains volunteer profiles with skills and availability, schedules shifts for events, and logs verified hours.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Volunteer** | `name` (text), `skills` (text), `availability` (text), `totalHours` (number), `status` (select: active, on-leave, alumni) | one-to-many → HourLog | -- |
| **Shift** | `event` (text), `date` (date), `volunteersNeeded` (number), `description` (text), `status` (select: open, filled, completed, cancelled) | one-to-many → HourLog | `completeShift` |
| **HourLog** | `hours` (number), `supervisor` (text), `verified` (boolean), `notes` (text), `loggedDate` (date) | many-to-one → Volunteer, many-to-one → Shift | `verifyHours` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init volunteer-coordination
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define your Object Types**

   Create the Volunteer, Shift, and HourLog types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: volunteer-coordination
   ✔ Volunteer — 5 props, 1 link, 0 actions
   ✔ Shift — 5 props, 1 link, 1 action
   ✔ HourLog — 5 props, 2 links, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Volunteer --data '{"name": "Carlos Mendez", "skills": "Event setup, registration desk, first aid", "availability": "Weekends and evenings", "totalHours": 120, "status": "active"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Code Example

```typescript

export const objectTypes = {
  'volunteer-coordination': [
    {
      name: 'Volunteer',
      displayName: 'Volunteer',
      description: 'A registered volunteer with the organization',
      properties: [
        { name: 'name', type: 'text' as const, required: true, indexed: true },
        { name: 'skills', type: 'text' as const, required: false },
        { name: 'availability', type: 'text' as const, required: false },
        { name: 'totalHours', type: 'number' as const, required: false, defaultValue: 0 },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'active', options: [
          { label: 'Active', value: 'active' },
          { label: 'On Leave', value: 'on-leave' },
          { label: 'Alumni', value: 'alumni' },
        ]},
      ],
      linkTypes: [
        { name: 'hourLogs', targetObjectType: 'HourLog', cardinality: 'one-to-many' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
    {
      name: 'Shift',
      displayName: 'Shift',
      description: 'A scheduled volunteer shift for an event or program',
      properties: [
        { name: 'event', type: 'text' as const, required: true, indexed: true },
        { name: 'date', type: 'date' as const, required: true, indexed: true },
        { name: 'volunteersNeeded', type: 'number' as const, required: true },
        { name: 'description', type: 'text' as const, required: false },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'open', options: [
          { label: 'Open', value: 'open' },
          { label: 'Filled', value: 'filled' },
          { label: 'Completed', value: 'completed' },
          { label: 'Cancelled', value: 'cancelled' },
        ]},
      ],
      linkTypes: [
        { name: 'hourLogs', targetObjectType: 'HourLog', cardinality: 'one-to-many' as const },
      ],
      actions: [
        {
          name: 'completeShift',
          displayName: 'Complete Shift',
          description: 'Mark a shift as completed after the event',
          requiredRole: 'tenant-staff',

            { type: 'set_field', field: 'status', value: 'completed' },
          ],
        },

      displayName: 'Hour Log',

        { name: 'supervisor', type: 'text' as const, required: true },
        { name: 'verified', type: 'boolean' as const, required: true, defaultValue: false },
        { name: 'notes', type: 'text' as const, required: false },
        { name: 'loggedDate', type: 'date' as const, required: true, indexed: true },
      ],
      linkTypes: [
        { name: 'volunteer', targetObjectType: 'Volunteer', cardinality: 'many-to-one' as const },

          ],
        },
      ],
      status: 'published' as const,
    },
  ],

```

## Key Takeaways

- **Skills-based matching**: Volunteer profiles with skills and availability enable coordinators to match the right people to the right shifts.
- **Verified hour tracking**: Supervisor verification on hour logs replaces unreliable self-reported timesheets with accountable records.
- **Shift lifecycle management**: Shifts flow from open through filled to completed, giving coordinators visibility into staffing levels for upcoming events.
- **Aggregate reporting**: Linking hour logs to both volunteers and shifts enables reports by individual, event, or time period for funder and board reporting.
