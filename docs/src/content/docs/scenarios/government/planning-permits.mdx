## Persona

**Role:** Planning Systems Analyst at a mid-sized county government.

You work in the Planning and Zoning department, responsible for digitizing the permit lifecycle. Your team processes hundreds of building, grading, and land-use permits each quarter. Paper forms and email-based reviews have led to missed deadlines and inconsistent decisions. You need a structured system that tracks every application from intake through final approval.

## Business Problem

The current permit workflow is fragmented across spreadsheets, shared drives, and email threads. Reviewers lack visibility into application status, applicants cannot self-serve on progress updates, and the department has no audit trail for approval decisions. You need a vertical application that provides:

- A single intake point for all permit types.
- Structured review assignments with recommendation tracking.
- Conditional approvals with expiry dates and enforceable conditions.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **PermitApplication** | type, address, description, status | has many Reviews, has one Approval | submit, assign-reviewer, withdraw |
| **Review** | application, reviewer, comments, recommendation | belongs to PermitApplication | complete-review, request-revision |
| **Approval** | application, authority, conditions, expiryDate | belongs to PermitApplication | grant, deny, extend |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init planning-permits
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define Object Types**

   Create your permit data model in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: planning-permits
   ✔ PermitApplication — 4 props, 2 links, 3 actions
   ✔ Review — 4 props, 1 link, 2 actions
   ✔ Approval — 4 props, 1 link, 3 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create a sample permit application**

   ```bash
   eai resources create PermitApplication \
     --data '{"type": "building", "address": "42 Elm St", "description": "Two-story residential addition", "status": "submitted"}'
   ```

7. **Query applications by status**

   ```bash
   eai resources list PermitApplication --filter 'status=submitted'
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Structured review workflow.** Linking Reviews to PermitApplications ensures every decision is traceable and no application falls through the cracks.
- **Status-driven lifecycle.** Select-type properties with defined options enforce a consistent permit lifecycle that maps directly to departmental procedures.
- **Conditional approvals with expiry.** The Approval type captures conditions and expiry dates, giving enforcement staff a clear reference for compliance follow-up.
- **Self-service visibility.** Applicants and staff can query permits by status, reducing phone inquiries and improving departmental transparency.
