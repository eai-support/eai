## Persona

**Role:** Digital Services Manager at a city government agency.

You oversee the city's 311-style service request system. Citizens report issues ranging from potholes to noise complaints, and each request must be triaged, assigned to the appropriate department, tracked through resolution, and scored for satisfaction. Your goal is to replace a legacy ticketing system with a modern vertical application.

## Business Problem

The existing system lacks visibility into request backlogs, does not enforce SLA timelines, and provides no structured way to capture resolution outcomes. Department heads cannot see aggregate metrics, and citizens receive inconsistent updates. You need:

- Categorized intake with priority assignment.
- Case management with clear ownership and status tracking.
- Resolution records that capture outcomes and citizen satisfaction.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **ServiceRequest** | citizen, category, description, priority | has one Case | submit, escalate, close |
| **Case** | request, assignedTo, status, timeline | belongs to ServiceRequest, has one Resolution | assign, update-status, escalate |
| **Resolution** | case, action, outcome, satisfactionScore | belongs to Case | resolve, reopen |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init citizen-services
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define Object Types**

   Add the ServiceRequest, Case, and Resolution types to `src/eai.config/object-types.ts`.

4. **Validate and seed**

   ```bash
   eai types validate
   eai types seed
   ```

   ```
   Tenant: citizen-services
   ✔ ServiceRequest — 4 props, 1 link, 3 actions
   ✔ Case — 4 props, 2 links, 3 actions
   ✔ Resolution — 4 props, 1 link, 2 actions

   ✔ All Object Types are valid
   ```

5. **Create a service request**

   ```bash
   eai resources create ServiceRequest \
     --data '{"citizen": "jane.doe@example.com", "category": "roads", "description": "Pothole on Main St near intersection with Oak Ave", "priority": "high"}'
   ```

6. **List open cases**

   ```bash
   eai resources list Case --filter 'status=open'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Categorized intake reduces triage time.** Predefined categories and priority levels ensure requests are routed to the correct department from the start.
- **Clear ownership through case assignment.** Every service request generates a case with an explicit assignee, eliminating ambiguity about who is responsible.
- **Satisfaction tracking closes the loop.** Capturing satisfaction scores on resolutions gives leadership actionable data for service improvement.
- **SLA enforcement becomes possible.** With structured status transitions and timeline fields, you can build alerts and dashboards that surface overdue cases.
