## Persona

**Role:** Compliance Manager at a multi-national retail company.

You are responsible for ensuring that every product sold across multiple markets meets local regulatory standards. Your catalog includes thousands of SKUs, each requiring certifications that vary by market -- safety labels, environmental ratings, import approvals. Expired certifications mean products must be pulled from shelves, costing the business revenue and reputation.

## Business Problem

Certification tracking is spread across vendor-provided PDFs, internal spreadsheets, and email threads with testing labs. When a certification expires, the team often discovers it only after a regulatory audit. There is no centralized view of which products are compliant in which markets. You need:

- A product catalog enriched with market-specific compliance metadata.
- Certification tracking with expiry dates and renewal alerts.
- An audit log that records every compliance-related event for each product.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Product** | name, sku, category, market | has many Certifications, has many AuditLogs | register, update-market, discontinue |
| **Certification** | product, standard, status, expiryDate | belongs to Product | issue, renew, revoke |
| **AuditLog** | product, event, user, timestamp | belongs to Product | (system-generated) |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init product-compliance
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define Object Types**

   Add Product, Certification, and AuditLog to `src/eai.config/object-types.ts`.

4. **Validate and seed**

   ```bash
   eai types validate
   eai types seed
   ```

   ```
   Tenant: product-compliance
   ✔ Product — 4 props, 2 links, 3 actions
   ✔ Certification — 4 props, 1 link, 3 actions
   ✔ AuditLog — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Register a product**

   ```bash
   eai resources create Product \
     --data '{"name": "EcoBlend Detergent", "sku": "ECO-DET-500", "category": "household", "market": "EU"}'
   ```

6. **Add a certification**

   ```bash
   eai resources create Certification \
     --data '{"product": "ECO-DET-500", "standard": "EU-Ecolabel", "status": "active", "expiryDate": "2027-06-30"}'
   ```

7. **List certifications expiring soon**

   ```bash
   eai resources list Certification --filter 'status=active'
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Market-specific compliance tracking.** Each product is tied to a market, enabling compliance teams to filter by region and see exactly which certifications apply.
- **Expiry-driven renewal workflows.** The expiryDate on Certifications enables automated alerts so that renewals happen before products fall out of compliance.
- **Immutable audit history.** AuditLog entries have no actions, ensuring the compliance event history is tamper-resistant and audit-ready.
- **SKU-level granularity.** Indexed SKU fields allow fast lookups across large catalogs, connecting certification status directly to inventory and sales systems.
