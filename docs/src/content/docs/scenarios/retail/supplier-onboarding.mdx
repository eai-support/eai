## Persona

**Role:** Procurement Lead at a large retail group.

You manage the process of evaluating, onboarding, and monitoring suppliers across multiple product categories. Each year, your team processes over 200 vendor applications. Approved vendors sign contracts with specific terms, and their performance is reviewed quarterly. The current process involves PDF application forms, manual contract filing, and ad-hoc performance conversations.

## Business Problem

Vendor applications arrive as email attachments with no standardized format. Contract terms are stored in a shared drive with no link to the original application. Performance reviews happen informally, and there is no structured score that feeds back into contract renewal decisions. You need:

- A standardized vendor application pipeline with status tracking.
- Contract management linked to approved vendors with term visibility.
- Quarterly performance reviews that produce a score tied to contract renewals.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **VendorApplication** | company, category, status, submittedDate | has one Contract | submit, review, approve, reject |
| **Contract** | vendor, terms, startDate, endDate | belongs to VendorApplication, has many PerformanceReviews | execute, amend, terminate |
| **PerformanceReview** | vendor, period, metrics, score | belongs to Contract | schedule, complete, flag-issue |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init supplier-onboarding
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define Object Types**

   Add VendorApplication, Contract, and PerformanceReview to `src/eai.config/object-types.ts`.

4. **Validate and seed**

   ```bash
   eai types validate
   eai types seed
   ```

   ```
   Tenant: supplier-onboarding
   ✔ VendorApplication — 4 props, 1 link, 4 actions
   ✔ Contract — 4 props, 2 links, 3 actions
   ✔ PerformanceReview — 4 props, 1 link, 3 actions

   ✔ All Object Types are valid
   ```

5. **Submit a vendor application**

   ```bash
   eai resources create VendorApplication \
     --data '{"company": "Artisan Foods Co.", "category": "food-beverage", "status": "submitted", "submittedDate": "2026-03-01"}'
   ```

6. **Create a contract**

   ```bash
   eai resources create Contract \
     --data '{"vendor": "artisan-foods", "terms": "Net 30, minimum order 500 units", "startDate": "2026-04-01", "endDate": "2027-03-31"}'
   ```

7. **List applications under review**

   ```bash
   eai resources list VendorApplication --filter 'status=under-review'
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Standardized application pipeline reduces procurement friction.** Every vendor goes through the same structured intake, eliminating inconsistency from ad-hoc email submissions.
- **Contract-linked applications create an audit trail.** The link between VendorApplication and Contract ensures that every supply agreement traces back to a vetted and approved application.
- **Performance scores drive data-driven renewals.** Quarterly PerformanceReviews produce numeric scores that inform contract renewal, amendment, or termination decisions.
- **Category-based vendor segmentation.** Categorizing vendors by product type enables procurement leads to assess supplier diversity and identify gaps in the vendor portfolio.
