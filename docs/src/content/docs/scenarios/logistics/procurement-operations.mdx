## Business Problem

Procurement teams need a model that connects intake, sourcing, evaluation, contracting, ordering, receiving, and supplier performance. Without it, savings programs and compliance controls disappear into email and spreadsheets.

## Required Object Model (22 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Demand and Sourcing

- `BusinessUnit` — requesting business unit
- `Requester` — internal requester
- `Requisition` — purchase request
- `Category` — spend category
- `Supplier` — supplier master
- `SupplierQualification` — supplier qualification
- `RFxEvent` — RFx sourcing event
- `BidResponse` — supplier bid response

### Commercial and Order Flow

- `EvaluationScore` — bid evaluation score
- `Contract` — commercial contract
- `PurchaseOrder` — purchase order
- `GoodsReceipt` — goods receipt
- `InvoiceMatch` — three-way match
- `SpendBudget` — budget line
- `ApprovalRoute` — approval workflow
- `CatalogItem` — approved catalog item

### Performance and Governance

- `SavingsOpportunity` — identified savings case
- `ComplianceCheck` — policy or sourcing control
- `RiskAlert` — supplier risk alert
- `SupplierPerformanceReview` — supplier scorecard
- `RenewalTask` — renewal or rebid task
- `DisputeCase` — supplier dispute case

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify supplier submissions and contract documents by category and sourcing event.
- Summarise evaluation outcomes, compliance gaps, and savings opportunities before award decisions.
- Generate supplier-performance and renewal worklists from contract dates, disputes, and scorecards.

## Why This Scenario Is High-Value

Procurement teams create value when they standardise sourcing and keep supplier risk visible. This scenario provides a single operating model for both commercial and compliance control.
