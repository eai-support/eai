## Business Problem

Travel management teams coordinate trip requests, bookings, approvals, policy checks, disruptions, expense recovery, and supplier relationships. A dedicated vertical helps service teams keep every traveller and booking decision connected.

## Required Object Model (22 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Traveller and Policy Context

- `Traveler` — traveller profile
- `CostCenter` — budget owner
- `TravelPolicy` — applicable policy
- `TripRequest` — trip request
- `Approval` — travel approval
- `Itinerary` — trip itinerary
- `AirBooking` — flight booking
- `HotelBooking` — hotel booking

### Trip Execution

- `GroundBooking` — ground transport booking
- `VisaTask` — visa or entry task
- `ExpenseReport` — expense claim
- `Receipt` — expense receipt
- `DutyOfCareAlert` — traveller risk alert
- `SupplierRate` — negotiated rate
- `UnusedTicket` — unused ticket credit
- `RefundCase` — refund workflow

### Service and Reporting

- `TravelDisruption` — trip disruption
- `ServiceRequest` — traveller support request
- `Profile` — traveller settings profile
- `LoyaltyProgram` — loyalty program record
- `CarbonEstimate` — trip emissions estimate
- `ReportingSnapshot` — management report snapshot

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify traveller emails and supplier notices into booking, disruption, or expense workflows.
- Summarise disruption impact and recommend next actions based on policy and traveller importance.
- Generate spend and duty-of-care insights from bookings, alerts, and expense patterns.

## Why This Scenario Is High-Value

Travel operations sit between customer service, compliance, and spend control. This scenario helps travel teams respond faster while keeping policy and reporting intact.
