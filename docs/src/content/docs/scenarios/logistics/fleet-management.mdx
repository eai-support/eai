## Persona

**Role**: Fleet systems developer at a delivery company operating 75 vehicles across three depots.

Vehicle maintenance is scheduled based on calendar reminders rather than actual mileage, fuel costs are tracked only at the fleet level with no per-vehicle breakdown, and there is no centralized record of vehicle condition or service history. When a vehicle breaks down, the operations team has no data to predict which vehicles are at risk.

## Business Problem

Unexpected vehicle breakdowns disrupt delivery schedules and cost the company in towing fees, emergency repairs, and missed deliveries. Without mileage-based maintenance tracking, vehicles are either serviced too frequently (wasting money) or too infrequently (risking breakdowns). Fuel costs are rising but the company cannot identify which vehicles are inefficient. This scenario builds a fleet management workflow that tracks vehicle status and mileage, schedules maintenance based on usage data, and logs fuel consumption per vehicle.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Vehicle** | `make` (text), `model` (text), `year` (number), `mileage` (number), `status` (select: active, maintenance, retired) | one-to-many → MaintenanceRecord, one-to-many → FuelLog | -- |
| **MaintenanceRecord** | `type` (select: oil-change, tires, brakes, inspection, repair), `date` (date), `cost` (number), `vendor` (text), `mileageAtService` (number) | many-to-one → Vehicle | -- |
| **FuelLog** | `date` (date), `gallons` (number), `cost` (number), `odometer` (number) | many-to-one → Vehicle | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init fleet-management
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Vehicle, MaintenanceRecord, and FuelLog types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: fleet-management
   ✔ Vehicle — 5 props, 2 links, 0 actions
   ✔ MaintenanceRecord — 5 props, 1 link, 0 actions
   ✔ FuelLog — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Vehicle --data '{"make": "Ford", "model": "Transit 250", "year": 2023, "mileage": 34500, "status": "active"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Mileage-based maintenance**: Recording mileage at each service enables scheduling based on actual usage rather than arbitrary calendar intervals.
- **Per-vehicle cost analysis**: Maintenance costs and fuel consumption tracked per vehicle reveal which units are expensive to operate and may be candidates for replacement.
- **Fuel efficiency monitoring**: Odometer readings on fuel logs enable calculation of miles-per-gallon trends, identifying vehicles with declining efficiency.
- **Complete vehicle history**: Linking maintenance records and fuel logs to vehicles creates a comprehensive service history that supports resale value documentation and warranty claims.
