## Business Problem

Freight brokers must coordinate shippers, carriers, lanes, loads, dispatch, tracking, accessorials, claims, and finance events. The work is real-time, exception-heavy, and margin-sensitive.

## Required Object Model (23 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Commercial and Dispatch Setup

- `Shipper` — shipping customer
- `Carrier` — motor carrier
- `Lane` — origin-destination lane
- `QuoteRequest` — quote request
- `LoadTender` — accepted load
- `RateConfirmation` — confirmed rate
- `Driver` — driver record
- `Vehicle` — tractor or trailer

### Execution and Tracking

- `DispatchPlan` — dispatch plan
- `PickupStop` — pickup event
- `DeliveryStop` — delivery event
- `TrackingEvent` — tracking update
- `PODDocument` — proof-of-delivery document
- `AccessorialCharge` — accessorial charge
- `DetentionEvent` — detention or delay event
- `ClaimCase` — cargo or service claim

### Finance and Oversight

- `Invoice` — broker invoice
- `PaymentRun` — carrier payment cycle
- `CapacitySignal` — market capacity signal
- `ComplianceDocument` — carrier compliance document
- `ExceptionCase` — service exception
- `CustomerUpdate` — customer communication
- `MarginReport` — load-level margin report

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify PODs, carrier documents, and exception messages into the right load record.
- Summarise load health across detention, claims, and service exceptions before customer updates.
- Generate margin and carrier-performance insight from accessorials, claims, and lane history.

## Why This Scenario Is High-Value

Brokerage operations depend on visibility across many parties moving quickly. This scenario gives brokers a structured way to manage both real-time execution and commercial control.
