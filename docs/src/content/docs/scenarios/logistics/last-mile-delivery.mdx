## Persona

**Role**: Platform developer at a last-mile delivery startup handling 1,000+ daily deliveries in an urban market.

Drivers receive assignments through a consumer messaging app, customers have no visibility into delivery timing, and proof of delivery is a photo texted to a dispatcher who saves it to a shared folder. When a customer claims non-delivery, there is no structured evidence to resolve the dispute. The startup needs a purpose-built delivery management platform.

## Business Problem

Last-mile delivery is defined by tight time windows and high customer expectations. When customers do not know when their delivery will arrive, they are unavailable at the door, causing failed deliveries and redelivery costs. When proof of delivery is informal, disputes are unresolvable. When driver assignments are managed through messaging apps, there is no audit trail, no performance data, and no way to reassign deliveries when a driver calls in sick. This scenario builds a last-mile delivery workflow that assigns packages to drivers with time windows, sends notifications to customers at key milestones, and captures structured proof of delivery.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **DeliveryAssignment** | `package` (text), `driver` (text), `timeWindow` (text), `address` (text), `status` (select: assigned, en-route, attempted, delivered, failed) | one-to-many → Notification, one-to-many → ProofOfDelivery | `markEnRoute` |
| **Notification** | `type` (select: assignment, en-route, delivered, failed), `sentAt` (date), `channel` (select: sms, email, push), `recipient` (text) | many-to-one → DeliveryAssignment | -- |
| **ProofOfDelivery** | `photo` (file), `signature` (text), `timestamp` (date), `notes` (text) | many-to-one → DeliveryAssignment | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init last-mile-delivery
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the DeliveryAssignment, Notification, and ProofOfDelivery types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: last-mile-delivery
   ✔ DeliveryAssignment — 5 props, 2 links, 1 action
   ✔ Notification — 4 props, 1 link, 0 actions
   ✔ ProofOfDelivery — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create DeliveryAssignment --data '{"package": "PKG-2025-08-001", "driver": "Ana Rodriguez", "timeWindow": "2:00 PM - 4:00 PM", "address": "456 Oak Ave, Apt 3B", "status": "assigned"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Customer communication**: Structured notifications at each delivery milestone (assigned, en route, delivered) keep customers informed and reduce failed delivery attempts.
- **Dispute resolution**: Photo and signature proof of delivery linked to specific assignments provides clear evidence when customers dispute receipt.
- **Multi-channel notifications**: Supporting SMS, email, and push notification channels ensures customers receive updates through their preferred communication method.
- **Driver performance data**: Timestamped status transitions on delivery assignments enable analysis of delivery times, success rates, and driver efficiency.
