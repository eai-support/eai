## Persona

**Role**: Logistics platform developer at a freight brokerage managing 500+ shipments per month.

The operations team tracks shipments through carrier portals, updates customers via manual email, and records delivery confirmations in spreadsheets. There is no unified view of where shipments are, which ones are delayed, or whether deliveries were confirmed. The company needs a centralized shipment tracking platform.

## Business Problem

Customers call asking "where is my shipment?" and operations staff must log into individual carrier portals to find the answer. Delayed shipments are discovered only when customers complain, because there is no proactive monitoring. Delivery confirmations are not systematically recorded, leading to billing disputes over whether goods were actually received. This scenario builds a shipment tracking workflow that captures the full lifecycle from origin to delivery, records tracking events at each milestone, and logs delivery confirmations with recipient signatures.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Shipment** | `origin` (text), `destination` (text), `carrier` (text), `status` (select: booked, in-transit, out-for-delivery, delivered, exception), `estimatedDelivery` (date) | one-to-many → TrackingEvent, one-to-many → Delivery | `dispatchShipment` |
| **TrackingEvent** | `location` (text), `status` (text), `timestamp` (date), `description` (text) | many-to-one → Shipment | -- |
| **Delivery** | `recipient` (text), `signature` (text), `timestamp` (date), `notes` (text) | many-to-one → Shipment | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init shipment-tracking
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define your Object Types**

   Create the Shipment, TrackingEvent, and Delivery types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: shipment-tracking
   ✔ Shipment — 5 props, 2 links, 1 action
   ✔ TrackingEvent — 4 props, 1 link, 0 actions
   ✔ Delivery — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Shipment --data '{"origin": "Los Angeles, CA", "destination": "Chicago, IL", "carrier": "FastFreight Logistics", "status": "booked", "estimatedDelivery": "2025-08-05"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Code Example

```typescript
// src/eai.config/object-types.ts
export const objectTypes = {
  'shipment-tracking': [
    {
      name: 'Shipment',
      displayName: 'Shipment',
      description: 'A freight shipment moving from origin to destination',
      properties: [
        { name: 'origin', type: 'text' as const, required: true, indexed: true },
        { name: 'destination', type: 'text' as const, required: true, indexed: true },
        { name: 'carrier', type: 'text' as const, required: true },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'booked', options: [
          { label: 'Booked', value: 'booked' },
          { label: 'In Transit', value: 'in-transit' },
          { label: 'Out for Delivery', value: 'out-for-delivery' },
          { label: 'Delivered', value: 'delivered' },
          { label: 'Exception', value: 'exception' },
        ]},
        { name: 'estimatedDelivery', type: 'date' as const, required: true, indexed: true },
      ],
      linkTypes: [
        { name: 'trackingEvents', targetObjectType: 'TrackingEvent', cardinality: 'one-to-many' as const },
        { name: 'deliveries', targetObjectType: 'Delivery', cardinality: 'one-to-many' as const },
      ],
      actions: [
        {
          name: 'dispatchShipment',
          displayName: 'Dispatch Shipment',
          description: 'Mark a booked shipment as dispatched and in transit',
          requiredRole: 'tenant-user',
          validationRules: { requiredFields: ['origin', 'destination', 'carrier'], requiredStatus: 'booked' },
          sideEffects: [
            { type: 'set_field', field: 'status', value: 'in-transit' },
          ],
        },
      ],
      status: 'published' as const,
    },
    {
      name: 'TrackingEvent',
      displayName: 'Tracking Event',
      description: 'A status update event during shipment transit',
      properties: [
        { name: 'location', type: 'text' as const, required: true },
        { name: 'status', type: 'text' as const, required: true },
        { name: 'timestamp', type: 'date' as const, required: true, indexed: true },
        { name: 'description', type: 'text' as const, required: false },
      ],
      linkTypes: [
        { name: 'shipment', targetObjectType: 'Shipment', cardinality: 'many-to-one' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
    {
      name: 'Delivery',
      displayName: 'Delivery',
      description: 'A delivery confirmation for a shipment',
      properties: [
        { name: 'recipient', type: 'text' as const, required: true },
        { name: 'signature', type: 'text' as const, required: false },
        { name: 'timestamp', type: 'date' as const, required: true, indexed: true },
        { name: 'notes', type: 'text' as const, required: false },
      ],
      linkTypes: [
        { name: 'shipment', targetObjectType: 'Shipment', cardinality: 'many-to-one' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
  ],
};
```

## Key Takeaways

- **End-to-end visibility**: Every shipment is tracked from booking through transit to delivery, answering "where is my shipment?" without calling the carrier.
- **Event-driven tracking**: Tracking events create a timestamped history of every location and status change, enabling proactive delay detection.
- **Delivery confirmation**: Recipient and signature data recorded at delivery provides proof of receipt that prevents billing disputes.
- **Exception handling**: The exception status flag surfaces problematic shipments that need immediate attention, separating them from normal transit flow.
