## Persona

**Role**: Industrial IoT developer at a plastics manufacturer operating 80+ machines across two plants.

Maintenance is entirely reactive -- machines break, technicians scramble to fix them, and the same failures repeat because there is no preventive maintenance schedule. Repair history lives in technicians' memories, spare parts usage is untracked, and downtime costs are estimated rather than measured. The company wants to shift from reactive to preventive maintenance.

## Business Problem

Unplanned downtime is the most expensive problem on the factory floor. Without maintenance schedules, equipment runs until failure. Without repair logs, the same issues are diagnosed from scratch each time. Without parts tracking, critical spares run out at the worst moments. This scenario builds an equipment maintenance system that schedules preventive maintenance, logs every repair with parts and duration, and provides a complete service history for each machine.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Equipment** | `name` (text), `type` (text), `location` (text), `lastService` (date), `status` (select: operational, maintenance, offline) | one-to-many → MaintenanceSchedule, one-to-many → RepairLog | -- |
| **MaintenanceSchedule** | `frequency` (select: daily, weekly, monthly, quarterly, annual), `nextDue` (date), `description` (text), `status` (select: active, paused) | many-to-one → Equipment | `completeMaintenance` |
| **RepairLog** | `issue` (text), `technician` (text), `duration` (number), `parts` (text), `cost` (number), `repairedDate` (date) | many-to-one → Equipment | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init equipment-maintenance
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define your Object Types**

   Create the Equipment, MaintenanceSchedule, and RepairLog types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: equipment-maintenance
   ✔ Equipment — 5 props, 2 links, 0 actions
   ✔ MaintenanceSchedule — 4 props, 1 link, 1 action
   ✔ RepairLog — 6 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Equipment --data '{"name": "Injection Molder #7", "type": "Injection Molding Machine", "location": "Plant A, Bay 3", "lastService": "2025-06-01", "status": "operational"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Preventive over reactive**: Scheduled maintenance with configurable frequencies shifts the plant from costly breakdowns to planned service windows.
- **Repair history**: A complete log of every repair, including parts used and time spent, enables pattern recognition for recurring failures.
- **Cost visibility**: Tracking repair costs and duration per machine helps justify equipment replacement decisions with hard data.
- **Machine-level profiles**: Linking schedules and repair logs to individual equipment creates a service history that follows each machine throughout its lifecycle.
