## Persona

**Role**: Manufacturing software engineer at a food processing company running three shifts across two facilities.

Production managers track orders on whiteboards, batch completion times are logged in paper notebooks, and quality checks happen at the end of each batch with results filed in binders. The company needs real-time visibility into production progress, batch yields, and quality results to meet regulatory reporting requirements.

## Business Problem

Without digital tracking, production managers cannot answer basic questions: How many units of Product X were completed today? What is the yield rate for the current batch? Did the last quality check pass? Shift handoffs lose information, and regulatory auditors require manual compilation of batch records that takes days to assemble. This scenario builds a production tracking system that links orders to batches with real-time status updates and embeds quality checks directly into the batch workflow.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **ProductionOrder** | `product` (text), `quantity` (number), `priority` (select: standard, rush, critical), `dueDate` (date), `status` (select: planned, in-progress, completed, cancelled) | one-to-many → Batch | `startProduction` |
| **Batch** | `startTime` (date), `endTime` (date), `yield` (number), `targetQuantity` (number), `status` (select: running, completed, rejected) | many-to-one → ProductionOrder, one-to-many → QualityCheck | `completeBatch` |
| **QualityCheck** | `inspector` (text), `result` (select: pass, fail, conditional), `notes` (text), `checkedAt` (date) | many-to-one → Batch | -- |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init production-tracking
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the ProductionOrder, Batch, and QualityCheck types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: production-tracking
   ✔ ProductionOrder — 4 props, 1 link, 1 action
   ✔ Batch — 5 props, 2 links, 1 action
   ✔ QualityCheck — 4 props, 1 link, 0 actions

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create ProductionOrder --data '{"product": "Organic Granola 500g", "quantity": 5000, "priority": "standard", "dueDate": "2025-08-01", "status": "planned"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Order-to-batch hierarchy**: Production orders break down into trackable batches, giving managers real-time visibility into how much of an order is complete.
- **Yield tracking**: Recording actual yield against target quantity enables continuous improvement and early detection of production inefficiencies.
- **Embedded quality checks**: Quality results are linked directly to the batch they were performed on, creating the traceability required for regulatory audits.
- **Shift-proof handoffs**: Digital batch records persist across shifts, eliminating the information loss that occurs with paper-based tracking during handovers.
