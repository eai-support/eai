## Business Problem

Insurance brokers juggle client onboarding, risk capture, market submissions, quote comparisons, binding, certificates, and renewal work across disconnected systems. A dedicated vertical gives the brokerage one operating model for revenue teams, service teams, and compliance reviewers.

## Required Object Model (24 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Client and Sales Intake

- `BrokerOrganization` — top-level brokerage account
- `Producer` — broker or account executive
- `ClientAccount` — insured customer master
- `Prospect` — pre-client pipeline record
- `MarketCarrier` — insurance carrier record
- `MarketAppetite` — carrier appetite by segment
- `Submission` — market submission package
- `ExposureSchedule` — structured client exposure data

### Placement and Policy Workflow

- `CoverageRequirement` — requested coverage profile
- `RiskAssessment` — placement risk summary
- `QuoteRequest` — request sent to a market
- `CarrierQuote` — quote returned by a carrier
- `QuoteComparison` — side-by-side market comparison
- `Binder` — binding confirmation
- `Policy` — bound policy record
- `EndorsementRequest` — mid-term policy change

### Service, Finance, and Governance

- `RenewalOpportunity` — renewal workflow entry
- `CommissionSchedule` — broker revenue terms
- `Invoice` — billing record
- `Payment` — received or remitted payment
- `CertificateRequest` — proof of insurance request
- `ClaimNotice` — claim intake tied to a policy
- `ServiceTask` — client servicing task
- `ComplianceCheck` — regulatory or placement control

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify client submission packs and extract exposure fields before markets are approached.
- Summarise quote differences and highlight gaps, exclusions, and servicing risks.
- Generate renewal worklists and draft client update notes from policy and claim activity.

## Why This Scenario Is High-Value

Brokerages win when they reduce turnaround time, improve quote quality, and keep renewals on track. This scenario supports high-volume placement work without losing the audit trail needed for regulated insurance operations.
