## Persona

**Role**: Full-stack developer at an insurtech company (250 employees) building a claims management platform for property and casualty insurers.

Each insurance carrier is onboarded as a separate tenant, maintaining independent claims data, adjuster assignments, and payment records. The platform must handle high claim volumes during catastrophic events while keeping carrier data strictly separated.

## Business Problem

Insurance claims processing involves multiple handoffs -- initial filing, documentation review, adjuster assignment, damage assessment, and payment authorization. When these steps live in separate systems, claims languish in queues, policyholders wait weeks for updates, and adjusters duplicate effort reviewing the same documentation. This scenario builds a unified claims pipeline from submission through payment.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Claim** | `policyNumber` (text), `type` (select: auto, property, liability, health), `amount` (number), `description` (text), `status` (select: filed, under-review, approved, denied, paid) | one-to-many → Adjudication, one-to-many → Payment | `fileClaim` |
| **Adjudication** | `adjuster` (text), `decision` (select: approve, deny, request-info), `approvedAmount` (number), `reasoning` (text), `reviewDate` (date) | many-to-one → Claim | `submitDecision` |
| **Payment** | `amount` (number), `method` (select: ach, check, direct-repair), `processedDate` (date), `status` (select: pending, processed, returned), `payee` (text) | many-to-one → Claim | `processPayment` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init insurance-claims
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Claim, Adjudication, and Payment types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: insurance-claims
   ✔ Claim — 5 props, 2 links, 1 action
   ✔ Adjudication — 5 props, 1 link, 1 action
   ✔ Payment — 5 props, 1 link, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create a sample claim**

   ```bash
   eai resources create Claim --data '{"policyNumber": "POL-2026-44821", "type": "property", "amount": 12500, "description": "Water damage from burst pipe in basement, affecting drywall and flooring", "status": "filed"}'
   ```

7. **List filed claims**

   ```bash
   eai resources list Claim
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Complete claims lifecycle**: The Claim, Adjudication, and Payment types cover every stage from initial filing through settlement, eliminating the need for separate tracking systems.
- **Adjuster decision tracking**: Every adjudication records the adjuster, decision reasoning, and approved amount, providing a defensible audit trail for regulatory review and dispute resolution.
- **Flexible payment methods**: The Payment type supports ACH, check, and direct repair vendor payments, accommodating different claim types and policyholder preferences.
- **Carrier-level isolation**: Each insurance carrier operates in a separate tenant, ensuring that claims data, adjuster assignments, and payment records are never accessible across carrier boundaries.
