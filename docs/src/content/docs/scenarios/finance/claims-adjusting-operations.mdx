## Business Problem

Claims adjusting teams need one workflow across first notice of loss, assignment, evidence collection, inspections, reserve updates, settlement recommendations, and recovery actions. Without a structured operating model, handoffs between adjusters, vendors, and finance teams create delays and leakage.

## Required Object Model (23 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Claim Intake and Assignment

- `ClaimNotice` — first notice of loss record
- `PolicySnapshot` — coverage details at loss date
- `CoverageCheck` — initial coverage validation
- `LossEvent` — incident facts and timeline
- `Claimant` — party making the claim
- `InsuredParty` — covered customer entity
- `Adjuster` — assigned handler
- `Assignment` — claim ownership record

### Investigation and Decisioning

- `Reserve` — financial reserve record
- `Inspection` — site or asset inspection
- `EvidenceItem` — photo or document evidence
- `VendorEstimate` — repair or service estimate
- `FraudSignal` — potential fraud indicator
- `SettlementOption` — settlement pathway
- `PaymentApproval` — approved settlement decision
- `Payment` — claim payment record

### Recovery and Oversight

- `RecoveryOpportunity` — potential reimbursement path
- `LitigationHold` — legal preservation control
- `CommunicationLog` — stakeholder communications
- `SLAClock` — service level timer
- `AuditTrail` — reviewable action log
- `SubrogationCase` — subrogation workflow
- `ComplaintCase` — complaint or escalation record

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify incoming evidence and tie it to the right loss event, claimant, and policy snapshot.
- Summarise investigation files for supervisors before reserve or settlement decisions are made.
- Flag anomalies in vendor estimates, fraud indicators, and complaints for specialist review.

## Why This Scenario Is High-Value

A structured claims platform reduces cycle time while improving consistency across reserves, settlement approvals, and recoveries. It also gives leadership a clearer operational view of leakage, vendor performance, and complaint risk.
