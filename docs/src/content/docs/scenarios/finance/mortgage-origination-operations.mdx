## Business Problem

Mortgage teams work across lead management, application capture, document collection, underwriting conditions, title, appraisal, disclosures, and closing. Each step depends on many documents and approvals, so a schema-driven workflow is critical for speed and auditability.

## Required Object Model (24 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Borrower and Application Intake

- `Borrower` — primary applicant
- `CoBorrower` — secondary applicant
- `Lead` — pre-application opportunity
- `Application` — loan application record
- `LoanProduct` — selected product terms
- `Property` — collateral property
- `IncomeDocument` — income verification file
- `AssetStatement` — asset verification record

### Processing and Underwriting

- `Liability` — declared liability record
- `CreditPull` — credit report result
- `UnderwritingCondition` — open condition or stipulation
- `AppraisalOrder` — ordered appraisal
- `AppraisalReport` — completed valuation report
- `TitleOrder` — title service request
- `TitleCommitment` — pre-closing title commitment
- `RateLock` — rate lock record

### Closing and Post-Close Control

- `DisclosurePackage` — borrower disclosure pack
- `ClosingDisclosure` — final disclosure
- `ProcessorWorkQueue` — processing task container
- `LoanEstimate` — initial estimate
- `UnderwritingDecision` — approve or deny outcome
- `ClosingPackage` — closing document set
- `FundingInstruction` — disbursement instruction
- `PostCloseAudit` — post-close quality review

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify borrower documents and extract income, asset, and liability data into structured objects.
- Summarise underwriting conditions and highlight blockers before closing readiness review.
- Generate post-close audit worklists from missing disclosures, title issues, and funding exceptions.

## Why This Scenario Is High-Value

Mortgage profitability depends on reducing fallout, compressing cycle times, and keeping regulators comfortable with the file trail. This scenario gives lenders a complete origination operating model rather than a patchwork of spreadsheets and inboxes.
