## Persona

**Role**: Senior developer at a payment processing company (400 employees) building an internal compliance monitoring platform.

The platform serves multiple merchant portfolios, each operating as a separate tenant. Compliance analysts need real-time visibility into suspicious transactions without accessing data from other merchant groups.

## Business Problem

Payment processors are required to monitor transactions for fraud, money laundering, and sanctions violations. Analysts currently sift through raw transaction logs in multiple dashboards, manually correlating alerts with investigation notes in email threads. This scenario builds a structured monitoring workflow where transactions are scored for risk, alerts are generated based on configurable rules, and investigations are tracked from detection through resolution.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Transaction** | `amount` (number), `from` (text), `to` (text), `timestamp` (datetime), `riskScore` (number), `currency` (text) | one-to-many → Alert | -- |
| **Alert** | `rule` (text), `severity` (select: low, medium, high, critical), `status` (select: open, investigating, resolved, false-positive), `createdAt` (datetime) | many-to-one → Transaction, one-to-many → Investigation | `escalateAlert` |
| **Investigation** | `analyst` (text), `findings` (text), `resolution` (select: confirmed-fraud, suspicious-activity, false-positive, inconclusive), `startDate` (date), `closedDate` (date) | many-to-one → Alert | `closeInvestigation` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init transaction-monitoring
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Transaction, Alert, and Investigation types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: transaction-monitoring
   ✔ Transaction — 6 props, 1 link, 0 actions
   ✔ Alert — 4 props, 2 links, 1 action
   ✔ Investigation — 5 props, 1 link, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create a sample transaction and alert**

   ```bash
   eai resources create Transaction --data '{"amount": 15420.00, "from": "ACCT-8827391", "to": "ACCT-4410052", "timestamp": "2026-03-08T14:32:00Z", "riskScore": 87, "currency": "USD"}'

   eai resources create Alert --data '{"rule": "high-value-transfer-new-recipient", "severity": "high", "status": "open", "createdAt": "2026-03-08T14:32:05Z"}'
   ```

7. **List open alerts**

   ```bash
   eai resources list Alert
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Risk-scored transactions**: Every transaction carries a `riskScore`, enabling rule-based alert generation and priority-based analyst workload distribution.
- **Alert-to-investigation traceability**: The chain from Transaction to Alert to Investigation provides a complete audit trail that satisfies regulatory examination requirements.
- **Escalation workflow**: The `escalateAlert` action allows analysts to raise severity levels and reassign alerts, ensuring that high-risk items receive senior review without manual status tracking.
- **Merchant portfolio isolation**: Each merchant group operates in a separate tenant, preventing cross-portfolio data access and ensuring compliance with data segregation requirements.
