## Persona

**Role**: Solutions architect at a community credit union consortium (12 credit unions, 300 employees total) building a shared loan origination platform.

Each credit union operates as a separate tenant with its own underwriting criteria and member data. The shared platform reduces development costs while maintaining complete data isolation between institutions.

## Business Problem

Loan applications move through multiple stages -- intake, credit evaluation, underwriting, and disbursement -- often across disconnected spreadsheets and email threads. Loan officers lack real-time visibility into application status, and credit check results are manually copied between systems. This scenario builds a structured loan processing pipeline where applications flow from submission through approval to disbursement with full traceability.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **LoanApplication** | `applicant` (text), `amount` (number), `term` (number), `purpose` (select: home, auto, personal, business), `status` (select: submitted, under-review, approved, denied, disbursed) | one-to-many → CreditCheck, one-to-many → Disbursement | `reviewApplication` |
| **CreditCheck** | `score` (number), `report` (text), `date` (date), `bureau` (text), `debtToIncomeRatio` (number) | many-to-one → LoanApplication | `runCreditCheck` |
| **Disbursement** | `amount` (number), `method` (select: ach, wire, check), `date` (date), `status` (select: pending, processed, failed), `referenceNumber` (text) | many-to-one → LoanApplication | `processDisbursement` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init loan-processing
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the LoanApplication, CreditCheck, and Disbursement types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: loan-processing
   ✔ LoanApplication — 5 props, 2 links, 1 action
   ✔ CreditCheck — 5 props, 1 link, 1 action
   ✔ Disbursement — 5 props, 1 link, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create a sample loan application**

   ```bash
   eai resources create LoanApplication --data '{"applicant": "Maria Gonzalez", "amount": 25000, "term": 60, "purpose": "auto", "status": "submitted"}'
   ```

7. **Query applications by status**

   ```bash
   eai resources list LoanApplication
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Full origination pipeline**: The LoanApplication, CreditCheck, and Disbursement types model the complete loan lifecycle from submission through funds transfer, replacing fragmented spreadsheet workflows.
- **Credit check integration**: The `runCreditCheck` action captures bureau-specific scores and debt-to-income ratios, giving underwriters structured data for consistent decision-making.
- **Consortium model**: Each credit union operates in its own tenant with independent underwriting criteria, while sharing the same platform infrastructure and codebase to reduce costs.
- **Disbursement traceability**: Every fund transfer is recorded with method, reference number, and status, providing a complete audit trail from approval to payment.
