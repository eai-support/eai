## Persona

**Role**: Full-stack developer at a mid-size property management firm (200+ units across 15 buildings).

The development team is replacing a patchwork of spreadsheets and legacy desktop software with a centralized platform that handles property listings, tenant records, and lease lifecycle tracking. The system must support multi-building portfolios with per-property scoping for on-site managers.

## Business Problem

Property managers juggle tenant communications, unit availability, and lease renewals across multiple buildings with no single source of truth. Vacancy data lives in one spreadsheet, tenant contact information in another, and lease terms in PDF folders. This scenario builds a unified property management workflow where units, tenants, and leases are linked together, giving managers instant visibility into occupancy, upcoming renewals, and tenant history.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Property** | `address` (text), `type` (select: residential, commercial, mixed-use), `units` (number), `status` (select: active, inactive) | one-to-many → Tenant, one-to-many → Lease | -- |
| **Tenant** | `name` (text), `contact` (text), `leaseStart` (date), `unit` (text) | many-to-one → Property | -- |
| **Lease** | `property` (text), `tenant` (text), `rent` (number), `term` (number), `status` (select: active, expired, pending) | many-to-one → Property, many-to-one → Tenant | `activateLease` |

## CLI Workflow

<Steps>

1. **Scaffold the project**

   ```bash
   eai init property-management
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define your Object Types**

   Create the Property, Tenant, and Lease types in `src/eai.config/object-types.ts` (see code example below).

4. **Validate the type definitions**

   ```bash
   eai types validate
   ```

   ```
   Tenant: property-management
   ✔ Property — 4 props, 2 links, 0 actions
   ✔ Tenant — 4 props, 1 link, 0 actions
   ✔ Lease — 5 props, 2 links, 1 action

   ✔ All Object Types are valid
   ```

5. **Seed types to the platform**

   ```bash
   eai types seed
   ```

6. **Create sample resources**

   ```bash
   eai resources create Property --data '{"address": "742 Evergreen Terrace", "type": "residential", "units": 24, "status": "active"}'
   ```

7. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Code Example

```typescript
// src/eai.config/object-types.ts
export const objectTypes = {
  'property-management': [
    {
      name: 'Property',
      displayName: 'Property',
      description: 'A managed property in the portfolio',
      properties: [
        { name: 'address', type: 'text' as const, required: true, indexed: true },
        { name: 'type', type: 'select' as const, required: true, options: [
          { label: 'Residential', value: 'residential' },
          { label: 'Commercial', value: 'commercial' },
          { label: 'Mixed-Use', value: 'mixed-use' },
        ]},
        { name: 'units', type: 'number' as const, required: true },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'active', options: [
          { label: 'Active', value: 'active' },
          { label: 'Inactive', value: 'inactive' },
        ]},
      ],
      linkTypes: [
        { name: 'tenants', targetObjectType: 'Tenant', cardinality: 'one-to-many' as const },
        { name: 'leases', targetObjectType: 'Lease', cardinality: 'one-to-many' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
    {
      name: 'Tenant',
      displayName: 'Tenant',
      description: 'A tenant occupying a unit in a property',
      properties: [
        { name: 'name', type: 'text' as const, required: true, indexed: true },
        { name: 'contact', type: 'text' as const, required: true },
        { name: 'leaseStart', type: 'date' as const, required: true },
        { name: 'unit', type: 'text' as const, required: true },
      ],
      linkTypes: [
        { name: 'property', targetObjectType: 'Property', cardinality: 'many-to-one' as const },
      ],
      actions: [],
      status: 'published' as const,
    },
    {
      name: 'Lease',
      displayName: 'Lease',
      description: 'A lease agreement between a tenant and property',
      properties: [
        { name: 'property', type: 'text' as const, required: true },
        { name: 'tenant', type: 'text' as const, required: true },
        { name: 'rent', type: 'number' as const, required: true },
        { name: 'term', type: 'number' as const, required: true },
        { name: 'status', type: 'select' as const, required: true, defaultValue: 'pending', options: [
          { label: 'Active', value: 'active' },
          { label: 'Expired', value: 'expired' },
          { label: 'Pending', value: 'pending' },
        ]},
      ],
      linkTypes: [
        { name: 'property', targetObjectType: 'Property', cardinality: 'many-to-one' as const },
        { name: 'tenant', targetObjectType: 'Tenant', cardinality: 'many-to-one' as const },
      ],
      actions: [
        {
          name: 'activateLease',
          displayName: 'Activate Lease',
          description: 'Mark a pending lease as active after signing',
          requiredRole: 'tenant-staff',
          validationRules: { requiredStatus: 'pending' },
          sideEffects: [
            { type: 'set_field', field: 'status', value: 'active' },
          ],
        },
      ],
      status: 'published' as const,
    },
  ],
};
```

## Key Takeaways

- **Portfolio-wide visibility**: Linking properties, tenants, and leases provides a single view of occupancy, rent rolls, and upcoming renewals across all buildings.
- **Lease lifecycle management**: The `activateLease` action enforces a structured transition from pending to active, preventing premature occupancy.
- **Multi-building scoping**: Each property operates within the same tenant but is individually addressable, supporting on-site managers with property-level filtering.
- **Rapid onboarding**: New properties and tenants can be added via CLI or the application UI, with validation ensuring data consistency from day one.
