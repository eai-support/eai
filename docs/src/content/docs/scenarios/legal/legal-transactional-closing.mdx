## Business Problem

Transactional legal teams must coordinate counterparties, diligence responses, checklists, redlines, sign-offs, funds flow, and post-close obligations. The workflow is deadline-driven and highly dependent on document packages and approval chains.

## Required Object Model (23 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Deal Setup and Diligence

- `Deal` — deal record
- `Client` — client entity
- `Counterparty` — counterparty entity
- `Entity` — legal entity
- `TermSheet` — deal term sheet
- `DiligenceRequest` — diligence request
- `DiligenceResponse` — diligence response
- `ChecklistItem` — closing checklist item

### Drafting and Closing

- `DraftDocument` — draft agreement
- `MarkupRound` — negotiation cycle
- `ApprovalMatrix` — approval structure
- `SignaturePacket` — signing packet
- `ClosingCondition` — condition precedent
- `FundsFlow` — funds-flow schedule
- `ClosingSet` — closing binder
- `CapTableUpdate` — cap-table update

### Post-Close Governance

- `ConsentRequest` — required consent
- `OpinionLetter` — opinion deliverable
- `FilingTask` — post-close filing
- `PostCloseObligation` — ongoing obligation
- `MatterWorkspace` — shared workspace
- `BillingMilestone` — billing trigger
- `RiskIssue` — transaction risk issue

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify diligence materials and tie them to the correct checklist item and risk issue.
- Summarise outstanding conditions and signature blockers before closing calls.
- Generate post-close obligation lists from signed documents and closing binders.

## Why This Scenario Is High-Value

Transactional practices live or die on coordination quality. A schema-driven closing workspace reduces last-minute surprises and makes post-close follow-through much easier to manage.
