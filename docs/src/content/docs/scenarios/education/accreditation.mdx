## Persona

**Role:** Accreditation Coordinator at a regional university.

You manage the institution's accreditation processes across multiple accrediting bodies -- regional, programmatic, and specialized. Each body defines standards that the university must demonstrate compliance with, and evidence must be collected, organized, and submitted on multi-year cycles. The last accreditation cycle involved hundreds of documents scattered across departments with no centralized tracking.

## Business Problem

Standards from different accrediting bodies are tracked in separate spreadsheets maintained by different offices. Evidence documents are stored in department-level shared drives, and there is no reliable way to confirm which standards have sufficient evidence and which have gaps. Accreditation reports are assembled manually in the months before a visit, creating a crisis-mode atmosphere. You need:

- A centralized standard registry organized by accrediting body and category.
- Evidence tracking linked to specific standards with submission dates.
- Report generation that aggregates compliance status and findings by period.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Standard** | body, code, description, category | has many Evidences | create, update, retire |
| **Evidence** | standard, document, description, submittedDate | belongs to Standard | upload, review, accept, reject |
| **AccreditationReport** | body, period, status, findings | links to Standards | generate, submit, revise |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init accreditation
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

3. **Define Object Types**

   Add Standard, Evidence, and AccreditationReport to `src/eai.config/object-types.ts`.

4. **Validate and seed**

   ```bash
   eai types validate
   eai types seed
   ```

   ```
   Tenant: accreditation
   ✔ Standard — 4 props, 1 link, 3 actions
   ✔ Evidence — 4 props, 1 link, 4 actions
   ✔ AccreditationReport — 4 props, 1 link, 3 actions

   ✔ All Object Types are valid
   ```

5. **Create a standard**

   ```bash
   eai resources create Standard \
     --data '{"body": "HLC", "code": "5.B.1", "description": "The institution has a well-developed process for budgeting and financial planning", "category": "resources"}'
   ```

6. **Upload evidence**

   ```bash
   eai resources create Evidence \
     --data '{"standard": "std-5b1", "document": "/evidence/budget-process-2026.pdf", "description": "Annual budget planning process documentation", "submittedDate": "2026-02-15"}'
   ```

7. **List standards missing evidence**

   ```bash
   eai resources list Standard --filter 'category=resources'
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Multi-body standard tracking eliminates silos.** A single registry covers HLC, ABET, AACSB, and other bodies, giving the accreditation coordinator a unified compliance view.
- **Evidence linked to standards reveals gaps early.** Filtering standards by category and checking linked evidence surfaces compliance gaps months before a site visit, not weeks.
- **Report lifecycle prevents last-minute scrambles.** Structured report statuses -- from draft through submission -- enforce a review process that spreads the workload over the full accreditation cycle.
- **Category-based organization mirrors accreditor expectations.** Grouping standards by category (mission, teaching and learning, resources) aligns the internal tracking system with how accrediting bodies structure their evaluations.
