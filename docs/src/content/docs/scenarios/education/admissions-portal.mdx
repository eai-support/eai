## Persona

**Role:** Director of Admissions Technology at a private university.

You oversee the technology stack supporting the admissions office, which processes 12,000 applications annually across undergraduate, graduate, and professional programs. Each application involves document collection, committee review, and a final decision with potential conditions. The existing portal is aging and cannot accommodate new program types without extensive custom development.

## Business Problem

Applications arrive through a web portal, but supporting documents -- transcripts, recommendation letters, test scores -- are uploaded to a separate file share with no automated link to the application. Committee members review applications in a spreadsheet, and decisions are communicated via mail merge. There is no single view of an application's completeness or decision status. You need:

- A unified application record with program and term tracking.
- Document management linked to applications with verification status.
- Structured decision records that capture committee outcomes and conditions.

## Object Types

| Name | Key Properties | Links | Actions |
|------|---------------|-------|---------|
| **Application** | applicant, program, term, status | has many Documents, has one Decision | submit, review, request-info |
| **Document** | application, type, fileUrl, verified | belongs to Application | upload, verify, reject |
| **Decision** | application, committee, outcome, conditions | belongs to Application | recommend, approve, deny, defer |

## CLI Workflow

<Steps>

1. **Scaffold the vertical**

   ```bash
   eai init admissions-portal
   ```

2. **Authenticate and pull environment**

   ```bash
   eai login
   eai env pull --include-secrets
   ```

   <Aside type="note">
     If you are an external developer, see [External Developer Setup](/eai-cli/guides/external-developers/) for login flags and manual environment configuration.
   </Aside>

3. **Define Object Types**

   Add Application, Document, and Decision to `src/eai.config/object-types.ts`.

4. **Validate and seed**

   ```bash
   eai types validate
   eai types seed
   ```

   ```
   Tenant: admissions-portal
   ✔ Application — 4 props, 2 links, 3 actions
   ✔ Document — 4 props, 1 link, 3 actions
   ✔ Decision — 4 props, 1 link, 4 actions

   ✔ All Object Types are valid
   ```

5. **Create an application**

   ```bash
   eai resources create Application \
     --data '{"applicant": "jordan.lee@email.com", "program": "ms-data-science", "term": "Fall 2026", "status": "submitted"}'
   ```

6. **Upload a document record**

   ```bash
   eai resources create Document \
     --data '{"application": "app-001", "type": "transcript", "fileUrl": "/uploads/transcript-jordan-lee.pdf", "verified": false}'
   ```

7. **List applications by program**

   ```bash
   eai resources list Application --filter 'program=ms-data-science'
   ```

8. **Start local development**

   ```bash
   eai dev
   ```

</Steps>

## Key Takeaways

- **Document completeness tracking prevents review delays.** Linking Documents to Applications with a verified flag lets the admissions office quickly identify incomplete applications before sending them to committee.
- **Program-specific filtering streamlines committee work.** Committee members can filter applications by program and term, focusing their review on the relevant applicant pool.
- **Conditional admissions are first-class records.** The Decision type captures conditions alongside outcomes, ensuring that conditional admits receive appropriate follow-up.
- **Unified application lifecycle.** From draft through submission to decision, every stage is captured in structured status fields, giving leadership real-time visibility into pipeline health.
