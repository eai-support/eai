## Business Problem

ERP implementation teams work across requirement capture, process mapping, design, configuration, data migration, testing, cutover, training, and hypercare. The delivery model is complex enough to need dedicated workflow objects.

## Required Object Model (22 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Program and Design Context

- `ClientProgram` — client program
- `Workstream` — workstream
- `Requirement` — implementation requirement
- `ProcessMap` — process map
- `GapIssue` — fit-gap issue
- `DesignDecision` — design decision
- `ConfigurationItem` — configuration item
- `MasterDataObject` — master data object

### Build and Test Workflow

- `MigrationBatch` — migration batch
- `TestCase` — test case
- `TestRun` — test run
- `Defect` — implementation defect
- `CutoverTask` — cutover task
- `TrainingSession` — training session
- `RoleMapping` — role mapping
- `IntegrationContract` — integration contract

### Governance and Adoption

- `ChangeRequest` — change request
- `RAIDItem` — risk, assumption, issue, or dependency
- `HypercareTicket` — hypercare ticket
- `Signoff` — formal sign-off
- `Milestone` — program milestone
- `BenefitTracker` — benefit tracker

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify requirement and defect records by workstream and process area.
- Summarise cutover readiness from test runs, open defects, and training completion.
- Generate hypercare priorities from issue patterns, role mappings, and integration failures.

## Why This Scenario Is High-Value

ERP projects fail when dependencies are hidden and governance is weak. This scenario provides one delivery model across business design, technical build, and adoption.
