## Business Problem

Medical administration teams coordinate scheduling, referrals, registration packets, authorisations, reminders, interpreter needs, transport support, and after-visit follow-up. The work is high volume and highly interdependent, which makes a strong workflow model essential.

## Required Object Model (23 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Patient and Appointment Flow

- `Patient` — patient record
- `Appointment` — scheduled visit
- `Referral` — incoming or outgoing referral
- `Department` — service department
- `Provider` — clinician record
- `CareTeam` — assigned care team
- `WaitlistEntry` — waitlist record
- `Authorization` — administrative authorisation

### Registration and Messaging

- `RegistrationPacket` — registration task pack
- `InsuranceCard` — captured insurance record
- `Consent` — signed consent
- `MessageThread` — patient communication thread
- `CallLog` — phone contact record
- `Task` — admin work item
- `Escalation` — escalated service issue
- `FacilityRoom` — room or clinic location

### Service Quality and Follow-up

- `VisitPrepChecklist` — pre-visit checklist
- `NoShowEvent` — no-show tracking
- `FollowUpOrder` — follow-up action
- `SatisfactionSurvey` — patient feedback
- `InterpreterRequest` — language support request
- `TransportationRequest` — transport service request
- `HandoverNote` — handover or coordination note

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Summarise inbound message threads and turn them into structured admin tasks.
- Classify registration packets and identify missing forms before the appointment date.
- Prioritise follow-up and no-show recovery work based on service-line rules and patient risk.

## Why This Scenario Is High-Value

Medical admin work is a major determinant of throughput and patient satisfaction. A dedicated hub reduces handoff failures and gives coordinators a single source of truth across clinics and departments.
