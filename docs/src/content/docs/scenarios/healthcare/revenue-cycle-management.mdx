## Business Problem

Revenue-cycle teams need a system that follows work from patient registration through eligibility, authorisations, coding, claims, denials, appeals, posting, and collections. Fragmented tooling creates avoidable denial volume and slows cash flow.

## Required Object Model (24 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Patient Access and Encounter Setup

- `Patient` — patient master record
- `Guarantor` — financially responsible party
- `Coverage` — insurance coverage record
- `EligibilityCheck` — eligibility verification result
- `PriorAuthorization` — authorisation case
- `Referral` — referral requirement
- `Encounter` — billable encounter
- `ChargeCapture` — captured billable charge

### Claims and Payment Workflow

- `Claim` — claim header
- `ClaimLine` — line-level claim record
- `Denial` — denial case
- `Appeal` — appeal workflow
- `PaymentPosting` — posted payment event
- `PaymentPlan` — patient payment arrangement
- `Statement` — patient statement
- `BalanceBucket` — aged receivable bucket

### Coding, Collections, and Governance

- `CodingTask` — coding work item
- `CodingRule` — coding policy
- `WorkQueue` — operational work queue
- `CollectorTask` — collections task
- `Remittance` — remittance advice
- `ContractRate` — payer contract rate
- `ProviderGroup` — billing provider group
- `AuditReview` — quality or compliance review

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify payer correspondence, remittances, and denial documents into the right work queues.
- Summarise denial patterns and surface coding or authorisation gaps before they become revenue leakage.
- Generate collector and appeal worklists based on aging, denial reason, and payer responsiveness.

## Why This Scenario Is High-Value

Revenue-cycle performance directly affects cash flow and patient experience. A single operating model gives hospitals and clinics better control over denials, collections, and payer follow-up.
