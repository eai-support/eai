## Business Problem

Pharmacy operations teams need to balance replenishment, formularies, benefit checks, prior authorisations, claim rejections, recalls, and controlled-substance compliance. Those workflows cut across procurement, patient service, and clinical support.

## Required Object Model (23 object types)

This scenario needs more than 20 object types because it spans intake, delivery, exceptions, governance, and reporting.

### Dispensing and Coverage Context

- `Facility` — care facility
- `PharmacySite` — pharmacy location
- `Prescriber` — ordering clinician
- `Patient` — patient record
- `MedicationMaster` — medication catalogue
- `FormularyRule` — coverage and formulary rule
- `InventoryLot` — lot-level inventory
- `PurchaseOrder` — stock replenishment order

### Payer and Dispense Workflow

- `Supplier` — inventory supplier
- `ReplenishmentRule` — stocking rule
- `DispenseOrder` — dispense workflow
- `PriorAuthorization` — authorisation request
- `BenefitCheck` — benefit verification
- `ClaimSubmission` — pharmacy claim
- `Rejection` — claim rejection
- `Appeal` — claim or benefit appeal

### Compliance and Support

- `ColdChainEvent` — cold-chain handling event
- `ControlledSubstanceLog` — controlled drug log
- `RecallNotice` — recall event
- `WasteRecord` — wastage record
- `TechnicianTask` — technician work item
- `ShiftRoster` — roster and staffing
- `ClinicalIntervention` — pharmacist intervention

## Delivery Workflow

1. Authenticate and choose the tenant you want to work in.

   ```bash
   eai login
   eai tenant select
   ```

2. Pull environment values, validate the type definitions, and seed the model.

   ```bash
   eai env pull --include-secrets
   eai types validate
   eai types seed
   ```

3. Verify that the full model is available for the active tenant before building UI and workflows.

   ```bash
   eai resources schema --format json
   eai verify calls --format json
   ```

4. Load pilot data and exercise the operational workflows for the scenario.

## AI and Document Opportunities

- Classify payer rejection notices and route them by rejection cause and drug class.
- Summarise recall, cold-chain, and controlled-substance exceptions for pharmacy leaders.
- Generate replenishment and benefit-resolution worklists from stock, rejection, and demand signals.

## Why This Scenario Is High-Value

Back-office pharmacy work sits between patient care, inventory control, and reimbursement. This scenario helps health systems keep medication access and compliance operating from one coherent platform.
