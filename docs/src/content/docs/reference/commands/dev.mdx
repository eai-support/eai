## Synopsis

```
eai dev [options]
```

## Description

`eai dev` starts the local development server for your vertical application. Before launching, it runs a set of pre-flight connectivity checks to verify that your environment is properly configured:

1. **Environment file**: Confirms `.env.local` exists and is loaded.
2. **API connectivity**: Checks that the PublicAPI gateway is reachable.
3. **Auth configuration**: Verifies that Entra CIAM client and tenant IDs are set.

After checks pass, the CLI starts the Next.js development server (with Turbopack enabled by default) and forwards all environment variables from `.env.local` to the dev server process.

This command must be run from within an EAI project directory.

## Options

| Option | Description | Default |
|--------|-------------|---------|
| `--port <port>` | Port number for the dev server | `3000` |
| `--turbo` | Use Turbopack for faster builds | `true` |
| `--no-turbo` | Disable Turbopack | -- |
| `--skip-checks` | Skip pre-flight connectivity checks | `false` |
| `-h, --help` | Display help for the command. | -- |

### When checks reveal issues

```bash
eai dev
```

```
Starting patient-intake

⚠ No .env.local found. Run `eai env pull` to sync from cloud.
⚠ PublicAPI not reachable. CRUD/chat operations may fail.
ℹ Run `eai verify` to diagnose connectivity.
⚠ Entra auth not configured. Login will not work.

ℹ Starting Next.js at http://localhost:3000/patient-intake
```

The dev server still starts even when warnings are present, but API-dependent features (CRUD, chat, login) will not function until the issues are resolved.

## Pre-flight Checks

| Check | Warning condition | Resolution |
|-------|-------------------|------------|
| `.env.local` | File is missing or empty | Run `eai env pull` |
| PublicAPI | Endpoint does not respond within 5 seconds | Check `BASE_URL_PUBLIC_API`, run `eai verify` |
| Auth config | `ENTRA_CLIENT_ID` or `ENTRA_TENANT_ID` not set | Run `eai env pull --include-secrets` |
