## Synopsis

```
eai tenant <subcommand> [options]
```

## Description

`eai tenant` manages tenants on the EAI platform. Tenants are organizational boundaries that isolate data and configuration. A vertical application is scoped to one or more tenants, and all resources, Object Types, and workflows operate within a tenant context.

Tenants can be organized hierarchically with parent-child relationships. The `list` subcommand only returns active tenants where the logged-in user has the `tenant-admin` role. When parent metadata is present in the platform membership payload, `--parent` scopes the result to child tenants under that parent.

`eai tenant create` is intentionally truthful about lifecycle state:

- `created` means the tenant record exists
- `bootstrapped` means the CLI successfully called the constrained first-admin bootstrap flow for a child tenant
- `usable` means a refreshed membership check confirmed the current login now has direct `tenant-admin` on that tenant

For child tenants, the CLI only auto-selects the new tenant when `usable` is confirmed.

This command must be run from within an EAI project directory and requires `BASE_URL_PUBLIC_API` to be set.

## Subcommands

### eai tenant list

List active tenants where the logged-in user is a `tenant-admin`, optionally scoped to a parent tenant.

```
eai tenant list [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--parent <id>` | Parent tenant ID to scope the listing | -- (lists all tenant-admin memberships) |
| `--format <format>` | Output format (`text` or `json`) | `text` |
| `--json` | Legacy alias for `--format json` | `false` |

### eai tenant info

Show detailed information about a specific tenant.

```
eai tenant info <id>
```

| Option | Description | Default |
|--------|-------------|---------|
| `<id>` | Tenant ID to inspect | Required |
| `--format <format>` | Output format (`text` or `json`) | `text` |
| `--json` | Legacy alias for `--format json` | `false` |

### eai tenant select

Choose the active tenant to work with for platform commands.

```
eai tenant select [tenant]
```

| Option | Description | Default |
|--------|-------------|---------|
| `[tenant]` | Tenant ID or slug to select without prompting | Interactive prompt when omitted |

### eai tenant create

Create a new tenant on the platform. When `--parent` is used, the CLI also attempts the safe first-admin bootstrap flow for the current login and then refreshes memberships before deciding whether the tenant is usable.

```
eai tenant create [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--name <name>` | Tenant name (required) | Required |
| `--slug <slug>` | Tenant slug in kebab-case (required) | Required |
| `--parent <id>` | Parent tenant ID for hierarchical tenants | -- |
| `--domain <domains>` | Comma-separated list of associated domains | -- |
| `--usecase <usecase>` | Tenant usecase (`council`, `retail`, `healthcare`, `finance`, `manufacturing`, `generic`) | `generic` |
| `--industry <industry>` | Signup/onboarding industry segment used for baseline defaults | -- |
| `--starter-template <key>` | Starter vertical template key | `blank-vertical-template` |
| `--format <format>` | Output format (`text` or `json`) | `text` |
| `--json` | Legacy alias for `--format json` | `false` |

Child bootstrap guardrails:

- The caller must already be direct `tenant-admin` on the parent tenant.
- The target must be an immediate child of that parent.
- The child must not already have a tenant admin.
- Parent child allowance is enforced from `limits.tenants`.

## Examples

### List tenant-admin memberships

```bash
eai tenant list
```

```
⠋ Fetching tenants...
✔ 3 tenant-admin memberships
→ patient-intake — Patient Intake (intake.myenterprise.ai) [tenant-admin]
→ claims-portal — Claims Portal (claims.myenterprise.ai) [tenant-admin]
→ admin-hub — Admin Hub [tenant-admin]
```

Only tenants where the current user has a `tenant-admin` membership are returned.

If none are returned, the command explains that no active tenant-admin memberships were found and points you to `eai whoami` for the authenticated tenant context. This avoids conflating authentication with tenant-administration access.

### List tenants under a parent

```bash
eai tenant list --parent 8f3a1b2c-d4e5-6789-abcd-ef0123456789
```

### List as JSON

```bash
eai tenant list --format json
```

```json
{
  "tenants": [
    {
      "id": "8f3a1b2c-d4e5-6789-abcd-ef0123456789",
      "displayName": "Patient Intake",
      "slug": "patient-intake",
      "domain": "intake.myenterprise.ai",
      "isActive": true,
      "roles": ["tenant-admin"]
    }
  ],
  "count": 1
}
```

### Select the active tenant

```bash
eai tenant select
```

```
? Select the tenant to work with now
❯ patient-intake (patient-intake)
  claims-portal (claims-portal)
  admin-hub (admin-hub)

✔ Active tenant set to patient-intake (8f3a1b2c-d4e5-6789-abcd-ef0123456789)
```

### Create a tenant

```bash
eai tenant create --name "Claims Portal" --slug claims-portal --domain claims.myenterprise.ai
```

```
⠋ Creating tenant "Claims Portal"...
✔ Created tenant claims-portal (a7c9e4d1-...)
```

### Create a child tenant

```bash
eai tenant create \
  --name "Claims Staff" \
  --slug claims-staff \
  --parent a7c9e4d1-b2c3-4567-89ab-cdef01234567 \
  --usecase generic \
  --starter-template blank-vertical-template
```

Example outcome when bootstrap succeeds:

```
⠋ Creating tenant "Claims Staff"...
✔ Created tenant claims-staff (a7c9e4d1-...)
ℹ Bootstrap: first tenant admin was provisioned for the current login.
✔ Usable: direct tenant-admin confirmed and the new tenant was selected.
```

Example outcome when the tenant record exists but direct admin is not yet confirmed:

```
⠋ Creating tenant "Claims Staff"...
✔ Created tenant claims-staff (a7c9e4d1-...)
⚠ Bootstrap not confirmed: TENANT_ADMIN_REQUIRED: Tenant admin role required for parent tenant 8f3a...
⚠ Usable: not yet confirmed. The tenant exists, but direct tenant-admin membership is not visible yet.
```

### Create a tenant with multiple domains

```bash
eai tenant create \
  --name "Multi-Region Portal" \
  --slug multi-region \
  --domain portal-us.example.com,portal-eu.example.com
```
