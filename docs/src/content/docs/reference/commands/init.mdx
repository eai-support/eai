## Synopsis

```
eai init [name] [options]
```

## Description

`eai init` scaffolds a new vertical application from the public template repo [eai-vertical-template](https://github.com/eai-tools/eai-vertical-template). It clones the template, customizes configuration files, generates an Object Types scaffold, installs Gofer AI terminal assets, sets up a deployment workflow, and initializes a fresh git repository.

If `name` is not provided on the command line, the CLI will prompt for it interactively along with other configuration options such as display name, tenant structure, and feature selection.

The generated project is a Next.js 15 application with EAI platform integration, including:

- A pre-configured `.env.local` with placeholder values
- An Object Types scaffold in `src/eai.config/object-types.ts`
- A GitHub Actions deployment workflow in `.github/workflows/deploy-demo.yml`
- A `CLAUDE.md` project reference file
- Gofer assets for Claude CLI, Codex CLI, Gemini CLI, and GitHub Copilot
- An initial git commit

## Gofer assets

Gofer installation is on by default. The generated repo includes:

| CLI or workflow | Installed files |
|-----------------|-----------------|
| Shared Gofer pipeline | `.specify/commands`, `.specify/scripts`, `.specify/templates`, `.specify/scripts/hooks`, `.specify/README.md` |
| Claude CLI | `.claude/commands`, `.claude/agents`, `.claude/settings.json` |
| Codex CLI | `.system/skills/gofer` and `.agents/skills/gofer` |
| Gemini CLI | `.gemini/commands/gofer` and `.gemini/extension.json` |
| GitHub Copilot | `.github/prompts`, `.github/instructions`, `.github/copilot-instructions.md`, `.github/skills` |

Start with `/0_business_scenario` in Claude CLI, `$gofer/1_gofer_research` in Codex CLI, `/gofer:1_gofer_research` in Gemini CLI, or the Gofer prompt/skill surfaces in GitHub Copilot.

## Options

| Option | Description | Default |
|--------|-------------|---------|
| `[name]` | Name for the vertical (kebab-case). Prompted interactively if omitted. | -- |
| `--from <repo>` | GitHub repo URL or local path for the template. | `https://github.com/eai-tools/eai-vertical-template.git` |
| `--skip-prompts` | Use defaults without interactive prompts. Requires `name` argument. | `false` |
| `--no-gofer` | Skip installing Gofer AI terminal assets. | `false` |
| `-h, --help` | Display help for the command. | -- |

### Interactive Prompts

When running without `--skip-prompts`, the CLI will ask:

| Prompt | Description | Default |
|--------|-------------|---------|
| Vertical name | kebab-case identifier (e.g., `patient-intake`) | Value of `[name]` argument |
| Display name | Human-readable name (e.g., `Patient Intake`) | Derived from vertical name |
| Description | Short description of the application | `<Display Name> vertical application` |
| Tenant structure | Single tenant, dual tenant, or multi-tenant hierarchy | Single tenant |
| Include AI chat? | Whether to include AI chat features | Yes |
| Include document management? | Whether to include document upload/classification | Yes |
| Auth provider | Entra ID CIAM, Entra ID B2B, or Dual | CIAM |

### Scaffold from a custom template

```bash
eai init my-vertical --from https://github.com/my-org/my-template.git
```

### Scaffold without Gofer

```bash
eai init my-vertical --no-gofer
```

Use this only for a bare vertical scaffold. Most EAI verticals should keep the default Gofer assets so AI terminals can run the same delivery workflow from the repo.

### If Git is not installed

`eai init` clones the template repository, so Git must be installed and available on your `PATH`.

Typical Windows error:

```text
✖ Failed to clone template
✗ `git` is required to scaffold from a repository source, but it is not installed or not on your PATH.
```

Install Git, reopen the terminal, and run `eai init` again:

```powershell
winget install --id Git.Git -e
```
