## Synopsis

```
eai init [name] [options]
```

## Description

`eai init` scaffolds a new vertical application from the public template repo [eai-vertical-template](https://github.com/eai-tools/eai-vertical-template). It clones the template, customizes configuration files, generates an Object Types scaffold, installs Gofer AI terminal assets, sets up a deployment workflow, and initializes a fresh git repository.

If `name` is not provided on the command line, the CLI will prompt for it interactively along with other configuration options: display name, description, the platform tenant this vertical should bind to, and feature flags.

The generated project is a Next.js 15 application with EAI platform integration, including:

- A pre-configured `.env.local` with placeholder values
- An Object Types scaffold in `src/eai.config/object-types.ts`
- A GitHub Actions deployment workflow in `.github/workflows/deploy-demo.yml`
- A `CLAUDE.md` project reference file
- Gofer assets for Claude CLI, Codex CLI, Gemini CLI, and GitHub Copilot
- An initial git commit

## Gofer assets

Gofer installation is on by default. The generated repo includes:

| CLI or workflow | Installed files |
|-----------------|-----------------|
| Shared Gofer pipeline | `.specify/scripts`, `.specify/templates`, `.specify/scripts/hooks`, `.specify/README.md` |
| Claude CLI | `.claude/commands`, `.claude/agents`, `.claude/settings.json` |
| Codex CLI | `.system/skills` and `.agents/skills` |
| Gemini CLI | `.agents/skills` |
| GitHub Copilot | `.github/prompts`, `.github/instructions`, `.github/copilot-instructions.md`, `.github/skills` |

Start with `/0_business_scenario` in Claude CLI, `$0_business_scenario` in Codex CLI, `gemini skills list --all` in Gemini CLI, or the Gofer prompt/skill surfaces in GitHub Copilot.

## Options

| Option | Description | Default |
|--------|-------------|---------|
| `[name]` | Name for the vertical (kebab-case). Prompted interactively if omitted. | -- |
| `--from <repo>` | GitHub repo URL or local path for the template. | `https://github.com/eai-tools/eai-vertical-template.git` |
| `--skip-prompts` | Use defaults without interactive prompts. Requires `name` argument. | `false` |
| `--tenant <id>` | Bind this vertical to the given platform tenant ID. Validated against PublicAPI before scaffolding. Useful for non-interactive runs. | active tenant from `~/.eai/tokens.json`, or blank if none |
| `--create-child-tenant` | **Not implemented.** Refuses with a pointer to `eai tenant create --parent` as a workaround. | `false` |
| `--no-gofer` | Skip installing Gofer AI terminal assets. | `false` |
| `-h, --help` | Display help for the command. | -- |

### Interactive Prompts

When running without `--skip-prompts`, the CLI will ask:

| Prompt | Description | Default |
|--------|-------------|---------|
| Vertical name | kebab-case identifier (e.g., `patient-intake`) | Value of `[name]` argument |
| Display name | Human-readable name (e.g., `Patient Intake`) | Derived from vertical name |
| Description | Short description of the application | `<Display Name> vertical application` |
| Which platform tenant should this vertical bind to? | Three-way choice — see [Tenant binding](#tenant-binding) below | Default (currently selected) |
| Include AI chat? | **Flag only — not implemented.** Captured but does not alter the scaffold today. | Yes |
| Include document management? | **Flag only — not implemented.** Captured but does not alter the scaffold today. | Yes |
| Auth provider | Entra ID CIAM (only implemented choice), B2B and Dual are listed as `[not implemented]` | CIAM |

If you're logged in and a tenant was successfully bound, the CLI also asks **"Provision Entra app registration now?"** after scaffolding completes. Answering yes runs Entra provisioning against the tenant you picked in the binding step and writes `ENTRA_CLIENT_ID` / `ENTRA_CLIENT_SECRET` into the new project's `.env.local`.

## Tenant binding

Every vertical binds to exactly one platform tenant. The tenant ID lands in the generated `.env.local` as both `EAI_TENANT_ID` (read by the Vertical-Template's server-side tenant resolver) and `TENANT_<NAME>_ID` (read by the template's multi-tenant config resolver). The two keys are kept in sync by `eai init`.

The interactive prompt offers three choices:

| Choice | What it does |
|--------|--------------|
| **Default (currently selected): `<name>` · `<id>`** | Binds to the active tenant from `~/.eai/tokens.json` (set by `eai login` + `eai tenant select`). If you're not logged in this choice is shown as disabled. |
| **Create a child tenant under the default `[not implemented]`** | Reserved slot. Selecting it hard-fails with a message pointing at the manual workaround (`eai tenant create --parent <id>`, then re-run `eai init --tenant <child-id>`). The underlying child-tenant bootstrap-admin path has a known live failure mode; `eai init` refuses to leave a half-provisioned child tenant bound to a fresh vertical. |
| **Other tenant (enter ID)** | Prompts for a tenant ID, validates it against PublicAPI via `GET /custom-tenants/{id}`, and binds if the tenant exists. Does **not** change the CLI's active-tenant state — this only affects the vertical being created. |

Non-interactive equivalents:

- `eai init my-app --skip-prompts` — uses the active tenant silently. Warns and leaves the tenant blank if you're not logged in.
- `eai init my-app --tenant <id> --skip-prompts` — binds to the given tenant ID after validating it exists.
- `eai init my-app --create-child-tenant` — refuses (stub). Same pointer to the workaround.

### Scaffold from a custom template

```bash
eai init my-vertical --from https://github.com/my-org/my-template.git
```

### Scaffold without Gofer

```bash
eai init my-vertical --no-gofer
```

Use this only for a bare vertical scaffold. Most EAI verticals should keep the default Gofer assets so AI terminals can run the same delivery workflow from the repo.

### If Git is not installed

`eai init` clones the template repository, so Git must be installed and available on your `PATH`.

Typical Windows error:

```text
✖ Failed to clone template
✗ `git` is required to scaffold from a repository source, but it is not installed or not on your PATH.
```

Install Git, reopen the terminal, and run `eai init` again:

```powershell
winget install --id Git.Git -e
```
