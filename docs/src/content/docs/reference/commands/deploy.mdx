## Synopsis

```
eai deploy <subcommand> [options]
```

## Description

`eai deploy` manages the deployment lifecycle for your vertical application. It generates GitHub Actions workflow files, configures deployment secrets, triggers deployments, and monitors their progress.

Deployments target Azure App Service and are triggered via GitHub Actions. The `trigger` and `status` subcommands use the GitHub CLI (`gh`) under the hood.

## Subcommands

### eai deploy setup

Generate a deployment workflow file and optionally configure GitHub repository secrets. Creates `.github/workflows/deploy-demo.yml` if it does not already exist.

```
eai deploy setup [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--repo <repo>` | GitHub repository in `org/name` format. When provided, lists required secrets. | -- |

The generated workflow requires these GitHub environment secrets (in the `demo` environment):

| Secret | Description |
|--------|-------------|
| `AZUREAPPSERVICE_CLIENTID` | Azure AD app registration client ID for deployment |
| `AZUREAPPSERVICE_TENANTID` | Azure AD tenant ID |
| `AZUREAPPSERVICE_SUBSCRIPTIONID` | Azure subscription ID |
| `AZURE_RESOURCE_GROUP` | Resource group name (e.g., `rg-demo-infrastructure`) |
| `AZURE_WEBAPP_NAME` | App Service name (e.g., `app-demo-eai-dev`) |

### eai deploy trigger

Trigger the deployment workflow on GitHub. Detects the repository from the git remote if `--repo` is not provided.

```
eai deploy trigger [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--repo <repo>` | GitHub repository in `org/name` format | Auto-detected from git remote |
| `--branch <branch>` | Branch to deploy | `main` |
| `--workflow <name>` | Workflow filename | `deploy-demo.yml` |

### eai deploy status

Check the status of recent deployments. Shows the last 5 workflow runs with their status, conclusion, branch, and timestamp.

```
eai deploy status [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--repo <repo>` | GitHub repository in `org/name` format | Auto-detected from git remote |

## Examples

### Generate deployment workflow

```bash
eai deploy setup
```

```
⠋ Generating deploy-demo.yml...
✔ Created .github/workflows/deploy-demo.yml

ℹ To configure GitHub secrets, re-run with --repo org/name
```

### Generate workflow and list required secrets

```bash
eai deploy setup --repo eai-tools/patient-intake
```

```
⠋ Generating deploy-demo.yml...
✔ Created .github/workflows/deploy-demo.yml

Configuring GitHub secrets
  Repository: eai-tools/patient-intake
ℹ Configure AZUREAPPSERVICE_CLIENTID: Azure AD app client ID for deployment
ℹ Configure AZUREAPPSERVICE_TENANTID: Azure AD tenant ID
ℹ Configure AZUREAPPSERVICE_SUBSCRIPTIONID: Azure subscription ID
ℹ Configure AZURE_RESOURCE_GROUP: Resource group name
ℹ Configure AZURE_WEBAPP_NAME: App Service name

ℹ Set secrets with: gh secret set SECRET_NAME --repo eai-tools/patient-intake
```

### Trigger a deployment

```bash
eai deploy trigger
```

```
⠋ Triggering deploy-demo.yml on eai-tools/patient-intake...
✔ Triggered deployment on eai-tools/patient-intake@main
ℹ Check status: eai deploy status --repo eai-tools/patient-intake
```

### Trigger deployment of a specific branch

```bash
eai deploy trigger --branch feature/new-intake-form
```

### Trigger a custom workflow

```bash
eai deploy trigger --workflow deploy-staging.yml --branch develop
```

### Check deployment status

```bash
eai deploy status
```

## Prerequisites

- **GitHub CLI** (`gh`) must be installed and authenticated for `trigger` and `status` subcommands.
- **Git remote**: The repository is auto-detected from the `origin` remote. Use `--repo` to override.
- **Azure**: Deployment targets Azure App Service. Secrets must be configured in the GitHub repository.

## Generated Workflow

The generated `deploy-demo.yml` performs these steps:

1. Checkout code
2. Set up Node.js 20
3. Install dependencies (`npm ci`)
4. Build Object Types JSON
5. Build the Next.js application
6. Package standalone output as a zip
7. Authenticate with Azure using OIDC
8. Deploy to Azure App Service
9. Restart the App Service
