## Synopsis

```
eai env <subcommand> [options]
```

## Description

`eai env` manages environment variables for your vertical application. Variables are stored in Azure App Configuration (with secrets in Azure Key Vault) and synced to a local `.env.local` file for development.

This command must be run from within an EAI project directory (a directory containing `src/eai.config/`).

## Subcommands

### eai env pull

Sync cloud configuration to your local `.env.local` file. Reads key-value pairs from Azure App Configuration, filtered by label (defaults to your app name).

Key Vault references are detected automatically. By default they are skipped with a comment; use `--include-secrets` to resolve and inline the actual secret values.

```
eai env pull [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--env <environment>` | Target environment (dev, test, prod) | `dev` |
| `--label <label>` | App Config label to filter by | App name from `NEXT_PUBLIC_APP_NAME` |
| `--include-secrets` | Resolve Key Vault references and include secret values | `false` |

### eai env list

Display the current environment variables from `.env.local`. Secret-looking values (keys containing SECRET, PASSWORD, KEY, TOKEN, or CREDENTIAL) are masked by default.

```
eai env list [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--show-secrets` | Show secret values instead of masking them | `false` |

### eai env push

Push local configuration overrides to Azure App Configuration. This is an admin operation -- use it to update cloud config from your local `.env.local`.

```
eai env push [options]
```

| Option | Description | Default |
|--------|-------------|---------|
| `--label <label>` | App Config label | App name from `NEXT_PUBLIC_APP_NAME` |
| `--key <key>` | Push a single key instead of all variables | -- (pushes all) |

## Examples

### Pull cloud config to local .env.local

```bash
eai env pull
```

```
⠋ Pulling config from appcs-demo-eai-dev (label: patient-intake)
✔ Found 12 config values
✔ NEXT_PUBLIC_APP_NAME = patient-intake
✔ APP_BASE_PATH = /patient-intake
✔ BASE_URL_PUBLIC_API = https://test-api.myenterprise.ai
ℹ ENTRA_CLIENT_SECRET = [Key Vault ref — skipped]
ℹ AUTH_SECRET = [Key Vault ref — skipped]
✔ ENTRA_TENANT_NAME = eaidevmyentepriseai
✔ ENTRA_TENANT_ID = 50808ce0-...
...

✔ Written to .env.local (12 variables)

⚠ 2 Key Vault references skipped. Use --include-secrets to resolve them.
```

### Pull with secrets resolved

```bash
eai env pull --include-secrets
```

```
⠋ Pulling config from appcs-demo-eai-dev (label: patient-intake)
✔ Found 12 config values
✔ NEXT_PUBLIC_APP_NAME = patient-intake
✔ ENTRA_CLIENT_SECRET = [from Key Vault]
✔ AUTH_SECRET = [from Key Vault]
...

✔ Written to .env.local (12 variables)
```

### Pull for a specific environment

```bash
eai env pull --env prod --label patient-intake-prod
```

### List current environment variables

```bash
eai env list
```

```
Environment (12 variables)
  NEXT_PUBLIC_APP_NAME = patient-intake
  APP_BASE_PATH = /patient-intake
  AUTH_SECRET = [hidden — use --show-secrets]
  BASE_URL_PUBLIC_API = https://test-api.myenterprise.ai
  ENTRA_CLIENT_ID = a1b2c3d4-...
  ENTRA_CLIENT_SECRET = [hidden — use --show-secrets]
  ENTRA_TENANT_ID = 50808ce0-...
  ENTRA_TENANT_NAME = eaidevmyentepriseai
  ...
```

### List with secrets visible

```bash
eai env list --show-secrets
```

### Push local config to cloud

```bash
eai env push
```

```
⠋ Pushing 12 values to appcs-demo-eai-dev (label: patient-intake)
✔ Pushed 12 values to appcs-demo-eai-dev (label: patient-intake)
```

### Push a single key

```bash
eai env push --key BASE_URL_PUBLIC_API
```

## Prerequisites

- **Azure CLI** (`az`) must be installed and authenticated (`az login`) for `pull` and `push` subcommands.
- The project must have a `src/eai.config/` directory (EAI project root detection).
