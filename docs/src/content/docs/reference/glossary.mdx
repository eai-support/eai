title: Glossary
description: Alphabetical listing of key terms used throughout the EnterpriseAI platform and CLI documentation.
---

## A

### Action

A named business operation declared in an [Object Type](#object-type) definition. Actions have a required role, validation rules (pre-conditions), and side effects (automated field changes). Actions are executed via the Platform API at `/v3/resources/{tenantId}/{objectType}/{id}/actions/{action}`.

See: [Data Model - Actions](/eai-cli/concepts/data-model/#actions), [Object Type Schema - Action Reference](/eai-cli/reference/object-type-schema/#action-reference)

## B

### BFF Proxy

**Backend-for-Frontend Proxy.** A server-side layer in Next.js applications that forwards requests to the [Platform API](#platform-api). The BFF proxy adds the user's access token (stored server-side) before forwarding, keeping credentials out of the browser.

See: [Architecture - BFF Proxy Pattern](/eai-cli/concepts/architecture/#bff-proxy-pattern)

## C

### Cardinality

The relationship multiplicity between two [Object Types](#object-type). Supported values: `one-to-one`, `one-to-many`, `many-to-one`, `many-to-many`. Defined on [Link Types](#link-type).

See: [Object Type Schema - Link Type Reference](/eai-cli/reference/object-type-schema/#link-type-reference)

### CLI

**Command Line Interface.** The `eai` tool (`@eai-tools/cli`) used to scaffold, validate, seed, deploy, and manage vertical business applications from the terminal. Installed globally via `npm install -g @eai-tools/cli`.

See: [Installation](/eai-cli/getting-started/installation/), [Quick Start](/eai-cli/getting-started/quickstart/)

## D

### Data Service

A backend service that manages data storage and retrieval for [resources](#resource). Part of the [platform service](#platform-service) layer. Not accessed directly -- all operations go through the [Platform API](#platform-api).

### Device Code Flow

An OAuth 2.0 authentication flow that allows the CLI to authenticate without requiring a browser on the same machine. The CLI displays a code and URL; the user opens the URL in any browser, enters the code, and signs in. Used by `eai login`.

See: [Architecture - Authentication Flow](/eai-cli/concepts/architecture/#authentication-flow), [Security Model - CLI Authentication](/eai-cli/concepts/security-model/#cli-authentication-device-code-flow)

## E

### Entra CIAM

**Microsoft Entra Customer Identity and Access Management.** The identity provider used for authentication in the EnterpriseAI platform. Handles user sign-up, sign-in, MFA, and token issuance.

See: [Security Model - Authentication](/eai-cli/concepts/security-model/#authentication)

## L

### Link Type

A declared relationship between two [Object Types](#object-type). Each link type has a name, target Object Type, [cardinality](#cardinality), and optional cascade delete behavior. Defined in the `linkTypes` array of an Object Type definition.

See: [Data Model - Links](/eai-cli/concepts/data-model/#links-relationships), [Object Type Schema - Link Type Reference](/eai-cli/reference/object-type-schema/#link-type-reference)

## O

### Object Type

The core data modeling abstraction in EnterpriseAI. An Object Type defines a category of [resource](#resource) with [properties](#property) (fields), [link types](#link-type) (relationships), [actions](#action) (business operations), and [side effects](#side-effect) (computed values). Defined in `src/eai.config/object-types.ts` and published to the platform with `eai types seed`.

See: [Data Model](/eai-cli/concepts/data-model/), [Object Type Schema](/eai-cli/reference/object-type-schema/)

## P

### Platform API

The central API gateway for the EnterpriseAI platform. All client-facing traffic (from the CLI, Platform SDK, and web applications) goes through the Platform API at `/v3/*`. Endpoints cover resources, chat, documents, authentication, and user management.

See: [Architecture](/eai-cli/concepts/architecture/), [API Surface](/eai-cli/reference/api-surface/)

### Platform SDK

A TypeScript library (`@eai-tools/platform-sdk`) used inside Next.js applications to interact with the [Platform API](#platform-api). Unlike the CLI (which calls the API directly), the SDK routes requests through the [BFF proxy](#bff-proxy).

### Platform Service

The backend service that manages [resources](#resource), [Object Type](#object-type) schemas, [tenants](#tenant), and users. Not accessed directly -- all operations go through the [Platform API](#platform-api).

### Property

A field definition within an [Object Type](#object-type). Each property has a name, type (`text`, `number`, `boolean`, `date`, `select`, `json`, `file`, or `relationship`), and optional constraints (`required`, `indexed`, `defaultValue`, `options`).

See: [Data Model - Properties](/eai-cli/concepts/data-model/#properties), [Object Type Schema - Field Type Reference](/eai-cli/reference/object-type-schema/#field-type-reference)

## R

### Resource

An instance of an [Object Type](#object-type). Resources are created, read, updated, and deleted through the Platform API. Each resource has an `id`, a `data` object (containing property values), a `version` (for optimistic locking), and timestamps (`created_at`, `updated_at`). Resources are always scoped to a [tenant](#tenant).

See: [API Surface - Resource Endpoints](/eai-cli/reference/api-surface/#resource-endpoints)

### Role

A permission level assigned to a user within a [tenant](#tenant). The platform defines three roles: `tenant-user`, `tenant-staff`, and `tenant-admin`. Roles control which resources a user can access and which [actions](#action) they can execute.

See: [Security Model - Roles](/eai-cli/concepts/security-model/#roles)

## S

### Side Effect

An automated field change applied when an [action](#action) is executed successfully. Side effect types: `set_field` (static value), `set_timestamp` (current time), `set_user` (authenticated user's ID). Side effects are atomic -- if any fails, the entire action is rolled back.

See: [Data Model - Side Effects](/eai-cli/concepts/data-model/#side-effects), [Object Type Schema - Side Effect Type Details](/eai-cli/reference/object-type-schema/#side-effect-type-details)

## T

### Tenant

An isolated organizational unit in the platform. Every [resource](#resource), conversation, and document is scoped to a tenant. Users belong to one or more tenants and have a [role](#role) within each. Tenants can be organized in a parent-child hierarchy. Tenant IDs are part of API URLs (`/v3/resources/{tenantId}/...`).

See: [Security Model - Multi-Tenant Data Isolation](/eai-cli/concepts/security-model/#multi-tenant-data-isolation)

## V

### Vertical

A **vertical business application** -- software designed for a specific industry or domain (healthcare, finance, government, etc.). Verticals encode domain-specific [Object Types](#object-type), workflows, and compliance rules. The EnterpriseAI platform and CLI are purpose-built for creating verticals.

See: [Verticals](/eai-cli/concepts/verticals/)

### Version (Optimistic Locking)

A numeric counter on each [resource](#resource) that increments with every update. When updating a resource, you must include the current `version` in the request. If the resource has been modified since you last read it (the version does not match), the update is rejected with a `409 Conflict` error.

See: [API Surface - Update Resource](/eai-cli/reference/api-surface/#update-resource)
