## HTTP Status Codes

The Platform API uses standard HTTP status codes. The most common ones you will encounter are listed below.

| Status | Meaning | When It Occurs |
|---|---|---|
| `200 OK` | Request succeeded | Successful GET, PUT, or action execution |
| `201 Created` | Resource created | Successful POST to create a resource |
| `204 No Content` | Deleted successfully | Successful DELETE |
| `400 Bad Request` | Malformed request | Invalid JSON, missing required fields in request body |
| `401 Unauthorized` | Not authenticated | Missing or expired access token |
| `403 Forbidden` | Not authorized | User's role is insufficient for the requested operation |
| `404 Not Found` | Resource not found | Invalid resource ID, Object Type, or tenant ID |
| `409 Conflict` | Version conflict | Optimistic locking failure -- the resource was modified since you last read it |
| `422 Unprocessable Entity` | Validation failed | Schema validation error, action pre-condition not met |
| `429 Too Many Requests` | Rate limit exceeded | Too many requests in the current window |
| `500 Internal Server Error` | Server error | Unexpected error on the platform side |

## Platform API Error Codes

All error responses include a machine-readable `code` field. Use this value for programmatic error handling.

### Authentication Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `AUTH_TOKEN_MISSING` | 401 | No authorization token provided | The `Authorization` header is missing | Include `Authorization: Bearer {token}` in the request |
| `AUTH_TOKEN_EXPIRED` | 401 | Access token has expired | The access token's expiry time has passed | Refresh the token or run `eai login` |
| `AUTH_TOKEN_INVALID` | 401 | Access token is invalid | The token is malformed or was issued by an untrusted authority | Run `eai login` to obtain a new token |
| `AUTH_REFRESH_FAILED` | 401 | Token refresh failed | The refresh token is expired or revoked | Run `eai login` to re-authenticate |

### Authorization Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `FORBIDDEN_ROLE` | 403 | Insufficient role for this operation | The user's role is lower than the action's `requiredRole` | Contact a tenant admin to upgrade the user's role |
| `FORBIDDEN_TENANT` | 403 | User does not belong to this tenant | The authenticated user is not provisioned in the target tenant | Run `eai verify` or provision the user into the tenant |
| `FORBIDDEN_RESOURCE` | 403 | Access denied to this resource | A `tenant-user` is trying to access another user's resource | Use a `tenant-staff` or `tenant-admin` account |

### Resource Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `RESOURCE_NOT_FOUND` | 404 | Resource not found | The resource ID does not exist or belongs to a different tenant | Verify the ID and tenant |
| `OBJECT_TYPE_NOT_FOUND` | 404 | Object Type not found | The Object Type name is not published for this tenant | Run `eai types seed` to publish the Object Type, or check the name spelling |
| `VERSION_CONFLICT` | 409 | Resource has been modified | The `version` in the update request does not match the current version | Re-fetch the resource to get the latest version, then retry |
| `VALIDATION_ERROR` | 422 | Validation failed | One or more fields failed schema validation | Check the `details` array for specific field errors |
| `ACTION_PRECONDITION_FAILED` | 422 | Action pre-conditions not met | Required fields are empty or the resource is not in the required status | Check `validationRules` in the action definition |
| `DUPLICATE_RESOURCE` | 409 | Resource already exists | A uniqueness constraint was violated | Check for existing resources with the same unique field values |

### Chat Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `WORKFLOW_NOT_FOUND` | 404 | Workflow not found | The workflow ID does not exist for this tenant | Verify the `WORKFLOW_DEFAULT_ID` or `--workflow` value |
| `CHAT_STAGE_INVALID` | 400 | Invalid chat stage | The stage name is not defined in the workflow | Check available stages for the workflow |
| `CHAT_STREAM_ERROR` | 500 | Stream connection failed | The AI service encountered an error while streaming | Retry the request; check AI service status if persistent |

### Document Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `DOCUMENT_TOO_LARGE` | 400 | File exceeds maximum size | The uploaded file is larger than the platform allows | Reduce file size or split into smaller documents |
| `DOCUMENT_TYPE_UNSUPPORTED` | 400 | Unsupported file type | The file format is not supported for classification | Check supported formats (PDF, DOCX, PNG, JPG, etc.) |
| `DOCUMENT_NOT_FOUND` | 404 | Document not found | The document ID does not exist | Verify the document was uploaded successfully |
| `INDEX_FAILED` | 500 | Document indexing failed | The RAG indexing process encountered an error | Retry; check that the document is in a supported format |

### Rate Limit Errors

| Code | HTTP Status | Message | Cause | Resolution |
|---|---|---|---|---|
| `RATE_LIMIT_EXCEEDED` | 429 | Rate limit exceeded | Too many requests from this tenant in the current window | Wait for the `Retry-After` period, then retry |

## CLI-Specific Errors

These errors are raised by the CLI itself, not the Platform API.

### Project Errors

| Error Message | Cause | Resolution |
|---|---|---|
| `Not in an EAI project.` | The current directory (or its ancestors) does not contain `eai.config.ts`, `src/eai.config/object-types.ts`, or a `package.json` with EAI dependencies | `cd` into your project directory, or run `eai init` to create a new project |
| `No object-types.ts found.` | The CLI could not find an Object Type definitions file | Create `src/eai.config/object-types.ts` in your project |
| `Failed to load Object Types` | The `object-types.ts` file has a syntax error or exports an unexpected structure | Check the file for TypeScript errors; ensure it exports `objectTypes` |

### Authentication Errors

| Error Message | Cause | Resolution |
|---|---|---|
| `Not authenticated.` | No stored token found at `~/.eai/tokens.json` | Run `eai login` |
| `Token expired. Please run eai login.` | Both the access token and refresh token have expired | Run `eai login` |
| `Device code flow timed out.` | The user did not complete sign-in within the timeout period | Run `eai login` again and complete the browser sign-in promptly |

### Environment Errors

| Error Message | Cause | Resolution |
|---|---|---|
| `BASE_URL_PUBLIC_API not set.` | The Platform API URL is not configured | Run `eai env pull` or set `BASE_URL_PUBLIC_API` in `.env.local` |
| `Missing BASE_URL_PUBLIC_API or tenant ID.` | Either the API URL or a tenant ID is missing | Set both `BASE_URL_PUBLIC_API` and `TENANT_DEFAULT_ID` in `.env.local` |
| `No tenant ID found for "{key}".` | No `TENANT_{KEY}_ID` environment variable matches the tenant key in `object-types.ts` | Add the matching `TENANT_{KEY}_ID` to `.env.local` |

### Validation Errors

| Error Message | Cause | Resolution |
|---|---|---|
| `name "{name}" must be PascalCase` | Object Type name does not match `/^[A-Z][a-zA-Z0-9]*$/` | Rename to PascalCase (e.g., `patientRecord` -> `PatientRecord`) |
| `missing displayName` | Object Type is missing the `displayName` field | Add a `displayName` string |
| `invalid status "{status}"` | Status is not `draft`, `published`, or `deprecated` | Use one of the three valid values |
| `duplicate property name "{name}"` | Two properties share the same name | Rename one of the duplicate properties |
| `select property "{name}" must have options` | A `select`-type property has an empty or missing `options` array | Add at least one option to the `options` array |

## Error Response Structure

All Platform API errors follow this structure:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Property 'firstName' is required",
    "details": [
      {
        "field": "firstName",
        "rule": "required",
        "message": "This field is required"
      }
    ]
  }
}
```

The `details` array is optional and only present for validation errors that affect specific fields.

<Aside type="tip">
  When debugging errors, use `--json` flag on CLI commands (e.g., `eai resources list Patient --json`) to see the full API response including error details.
</Aside>
