## Synopsis

All `eai` commands support these global options:

```bash
eai [global-options] <command> [command-options]
```

## Global Options

### `--describe`

Output a complete JSON schema of the CLI structure for programmatic consumption.

```bash
eai --describe
```

**Output:** JSON object with:
- `command`: CLI name
- `version`: CLI version
- `description`: CLI description
- `globalOptions`: Array of global option definitions
- `commands`: Array of all commands with their options and subcommands

**Use cases:**
- AI coding agents parsing CLI capabilities
- Automated tooling generation
- CLI structure validation

**Example output:**

```json
{
  "command": "eai",
  "version": "0.1.4",
  "description": "Enterprise AI Platform CLI",
  "globalOptions": [
    {
      "flags": "--simple",
      "description": "Plain text output without colors or symbols"
    },
    {
      "flags": "--describe",
      "description": "Output JSON schema of all commands"
    }
  ],
  "commands": [
    {
      "name": "init",
      "description": "Create a new vertical application",
      "options": [...]
    }
  ]
}
```

---

### `--format <format>`

Control output format for data-returning commands.

```bash
eai resources list User --format json
eai tenant list --format json | jq '.tenants[] | .slug'
eai deploy status --format json
```

**Valid formats:**
- `text` (default) — Human-readable formatted output
- `json` — Machine-readable JSON
- `yaml` — YAML format (planned, not yet implemented)

**Supported commands:** `resources list`, `resources get`, `tenant list`, `deploy status`, and all commands returning data

**Example:**

```bash
# Text format (default)
eai resources list User --limit 3

# → User-123 — John Doe (john@example.com)
# → User-456 — Jane Smith (jane@example.com)
# → User-789 — Bob Johnson (bob@example.com)

# JSON format
eai resources list User --limit 3 --format json

# {
#   "docs": [
#     { "id": "User-123", "firstName": "John", "lastName": "Doe" },
#     { "id": "User-456", "firstName": "Jane", "lastName": "Smith" },
#     { "id": "User-789", "firstName": "Bob", "lastName": "Johnson" }
#   ],
#   "totalDocs": 42,
#   "hasNextPage": true
# }
```

### `--simple`

Plain text output without colors or symbols for screen readers and accessibility.

```bash
eai --simple resources list User
```

**Output changes:**
- No ANSI color codes
- Symbols replaced with text:
  - ✓ → `SUCCESS:`
  - ✗ → `ERROR:`
  - ⚠ → `WARNING:`
  - → → `INFO:`
- Compatible with screen readers
- Suitable for log files and non-TTY environments

**Example:**

```bash
# Normal output
eai login
# → ✓ Login successful
# → User: john@example.com

# Simple mode
eai --simple login
# → SUCCESS: Login successful
# → INFO: User: john@example.com
```

---

### `--no-color`

Disable colored output (respects `NO_COLOR` environment variable).

```bash
eai --no-color resources list User
```

**Alternative:** Set `NO_COLOR=1` environment variable

**When to use:**
- Piping output to files
- CI/CD environments
- Terminals that don't support ANSI colors
- When colors interfere with readability

---

### `--color`

Force colored output even when stdout is not a TTY.

```bash
eai --color resources list User | less -R
```

**Alternative:** Set `FORCE_COLOR=1` environment variable

**When to use:**
- Piping to pagers that support colors (`less -R`)
- Logging with color preservation
- Debugging output formatting

---

## Environment Variables

The CLI respects standard color control environment variables:

| Variable | Effect | Equivalent Flag |
|----------|--------|-----------------|
| `NO_COLOR=1` | Disable colors globally | `--no-color` |
| `FORCE_COLOR=1` | Enable colors globally | `--color` |

**Precedence:** Command-line flags override environment variables.

**Example:**

```bash
# Disable colors via environment
export NO_COLOR=1
eai resources list User  # No colors

# Override with flag
eai --color resources list User  # Forces colors despite NO_COLOR
```

---

## Combining Options

Global options can be combined with command-specific options:

```bash
# Accessible JSON output
eai --simple --format json resources list User

# Describe with forced colors
eai --color --describe

# Simple mode with no colors (redundant but allowed)
eai --simple --no-color tenant list
```

## AI Coding Agent Integration

The `--describe` and `--format json` options are designed for AI coding agents and automation tools:

```bash
# Agent discovers CLI structure
eai --describe > cli-schema.json

# Agent parses capabilities
cat cli-schema.json | jq '.commands[] | .name'

# Agent executes commands with JSON output
eai resources list User --format json | jq '.docs[] | {id, name: (.firstName + " " + .lastName)}'

# Agent handles errors programmatically
eai resources get User invalid-id --format json 2>&1 | jq '.error.code'
# → "E202"
```

See [Error Codes](/reference/error-codes/#structured-error-codes) for structured error handling.
